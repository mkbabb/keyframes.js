# C.W2 — The design system made true (φ-ladder + serif + tokens)

THE headline design wave — the body of work A booked, B claimed-as-home and
then re-deferred while marking W5 done (`plan-findings.txt` deferred-ledger
[HIGH] §5; plan-fidelity [HIGH] §4). The demo forks glass-ui's φ type-ladder
wholesale: 267 raw Tailwind rungs across 8 sizes bolted to a hand-rolled
`.instrument-serif` alias (44 source sites / 20 files), `--font-display` is
*never defined* so every glass-ui display rung silently falls to Georgia, and
three load-bearing CSS custom properties the demo's own animations depend on
(`--dock-menubar-reserve`, `--spring-snappy`) are undefined — the
controls-pane slide is broken right now. C.W2 makes the demo speak ONE design
language: it ADOPTS glass-ui's semantic ladder (the utilities are already
imported — `node_modules/@mkbabb/glass-ui/dist/styles/typography.css:152-351`
ship `text-display-*`/`text-heading`/`text-subheading`/`text-title`/`text-body`/`text-small`/`text-caption`/`text-admin-label`/`dock-label`/`text-prose`),
formalizes ONE display serif in the token, and routes every off-token literal
to its canonical glass-ui token. Net-deletion adoption of already-shipped
glass-ui surfaces — not net-new CSS. Grounds: `design-findings.txt`
typography-ladder (Findings 1-6 + the class-by-class mapping table),
color-token (Findings 1-3), layout-rhythm (Findings 2,3,6), component-idiom
(Findings 2,3); `plan-findings.txt` deferred-ledger §5.

## § Goal

**What lands:** the demo rides glass-ui's golden-ratio (√φ) type ladder
instead of forking it — the 267 raw rungs and the 44 `.instrument-serif`
alias sites retire onto the semantic `.text-*` utilities; `--font-display` is
formalized to Instrument Serif (the demo's deliberate display voice) so the
ladder resolves correctly with zero new font payload; the three localized
off-token sites (CSSCodeEditor cartoon-shadow, SquareScene halo, EasingTarget
global `.glass-card` leak) consume canonical glass-ui tokens; and the three
undefined load-bearing layout properties (`--dock-menubar-reserve`,
`--spring-snappy`, the `--work-area-vertical-bias` rationale) are
defined/derived so the broken controls-pane animations work. A consumption
sweep proves zero raw display rung on the hero, zero `.instrument-serif`
residue, zero off-token literal in the swept files.

**Why:** this is the single most load-bearing visual decision in the product
and the headline B re-deferred to a phantom "next demo-touching wave" — C IS
that wave; it cannot punt a third time (`plan-findings.txt` deferred-ledger
§5, the P-invariant-28 TEMPORARY item). The fork is not cosmetic: the demo's
headings and the glass-ui components it embeds (dock, cards, popovers) sit on
two incommensurate scales (Tailwind's 1.25 ratio vs glass-ui's 1.272 √φ),
`--font-display` being undefined means adopting the ladder naively renders the
hero in Georgia, and two undefined `--spring-*`/reserve tokens make live
animations silently invalid. One adoption pass closes the design-language
fork, fixes the broken motion, and is net-deletion.

## § Scope

### S1 — Adopt glass-ui's φ-ladder: the class-by-class display/heading migration — typography-ladder F1,F4,F5

**WHAT:** migrate every raw Tailwind display/heading rung onto the semantic
glass-ui φ-ladder utility that bundles font-family + size + line-height +
tracking + weight + balance, per the audit's class-by-class mapping table
(`design-findings.txt` typography-ladder § "Class-by-class migration mapping
table"). The headline-tier sites (ship together, fully visible in the home +
easing captures):
- **Hero h1** — `EditorStartScreen.vue:6` `class="instrument-serif grid p-0
  text-6xl lg:flex lg:text-8xl"` → `.text-display-4` (φ^(7/2), clamp
  3.33→5.382rem). The fluid clamp REPLACES the `lg:text-8xl` breakpoint hop;
  `text-wrap: balance`, `--type-tracking-tight`, `--type-leading-display`
  come for free. Keep the orthogonal `.depth-text` (glass-ui) + the
  `AnimatedText` stagger — they compose with any type class.
- **h2 subtitle** — `EditorStartScreen.vue:22` `instrument-serif w-full
  text-5xl font-light italic` → `.text-title` + `italic` (drop `font-light` —
  title weight is intentional).
- **h2 hint** — `EditorStartScreen.vue:28` `instrument-serif w-full text-2xl
  font-light italic opacity-50` → `.text-subheading` + `italic
  text-muted-foreground` (mute by colour, not alpha — the audacious-canon
  precedent; opacity multiplies into the background and breaks contrast math).
- **Cube face number** — `CubeTarget.vue:70` `instrument-serif text-5xl
  font-bold` → `.text-display-2` (φ^(5/2) poster numeral).
- **Card titles** — `KeyframesEditor.vue:84`, `MatrixEditor.vue:48` `text-3xl`
  → `.text-heading` (the canonical section-title rung).
- **Target name spans** — `EasingTarget.vue:8`, `SpringTarget.vue:7`
  `instrument-serif text-xl lg:text-2xl` → `.text-heading` (clamp removes the
  `lg:` hop).
- **Dock trigger/select labels** — `TopDock.vue:146,151,172,178,214`,
  `AnimationMenuBar.vue:33,43,118,124` `instrument-serif text-lg`/`text-xl`
  (and `AnimationMenuBar.vue:118` even STACKS `dock-label instrument-serif
  text-lg`) → bare `.dock-label` (`+ font-semibold` for the selected-animation
  name). `dock-label` is glass-ui's purpose-built dock register (weight 400,
  `--type-subheading` size, `--font-display` pinned) — the demo half-knows
  this already; remove the override stack.

**WHY:** the hero is C's deferred HEADLINE — currently an arbitrary `text-8xl`

type decision sitting on the raw scale (`design-findings.txt`

scale fighting the ladder (F4 [MED]); the dock labels ignore the
purpose-built `dock-label` register and stack three classes fighting over one
element (F5 [MED]). Adopting the semantic utility per element collapses 8 raw
sizes to ~6 √φ registers, each inheriting correct line-height/tracking/weight/
balance — pure adoption of already-shipped glass-ui surfaces, net-deletion.

### S2 — Formalize ONE display serif in `--font-display` — typography-ladder F2,F3 + design-decision 2

**WHAT:** two coupled token moves that MUST land in the same change as S1
(without them the ladder renders Georgia):
- **Define** `--font-display: "Instrument Serif", Georgia, serif;` in
  `demo/@/styles/style.css` `@theme` block (alongside `--font-serif` at
  `style.css:7`). glass-ui's `text-display-*`/`text-title`/`text-heading` all
  resolve `font-family: var(--font-display)` which defaults to Fraunces — a
  face the demo never loads (verified: the lone `--font-display` reference in
  the whole demo is `AssetViewport.vue:52` *reading* it, ZERO definitions). So
  the demo's display rungs currently fall to Georgia. Formalizing Instrument
  Serif as the display voice (the demo's existing character) makes the ladder
  resolve correctly with zero new font payload. Instrument Serif is
  single-weight ~400 — the default `--font-display-weight: 400` is correct;
  the Fraunces `WONK`/`SOFT` axes no-op gracefully on a non-Fraunces face.
- **Delete** the `.instrument-serif` alias from `demo/@/styles/utils.css:84-87`
  (`{ font-family: var(--font-serif); letter-spacing: 0.02em; }`) after the
  sweep retires all 44 sites. The alias re-implements what the semantic serif
  classes already encode (font-family + tracking), forcing every site to ALSO
  hand-pick a raw rung. The baked `0.02em` tracking is design noise — the
  ladder's per-register `--type-tracking-*` is the correct intentional
  tracking.

**WHY:** RESOLVED design decision — Instrument Serif IS the demo's deliberate
identity face, so the gestalt is to formalize it as the `--font-display`
TOKEN (a token decision, not a per-surface override), not to alias
`.instrument-serif` onto raw rungs (`design-findings.txt` typography-ladder
F2 [HIGH], F3 [HIGH]; C.md §Resolved-design-decision 2). `--font-display`
being undefined is the prerequisite defect — it must land in the same change
or the migration renders the hero in Georgia (F2: "prerequisite for the whole
migration"). `.instrument-serif` is legacy by the MANDATE — removed, not kept
beside the semantic classes (no-alias).

### S3 — Token migrations: cartoon-shadow, SquareScene halo, EasingTarget global leak — color-token F1,F2,F3 + component-idiom F2,F3

**WHAT:** route the three localized off-token sites to their canonical
glass-ui tokens (all targets already exist — zero new tokens required):
- **CSSCodeEditor cartoon shadow** — `CSSCodeEditor.vue:6` `border-2
  border-gray-700 shadow-[4px_4px_0px_0px_rgba(0,0,0,0.6)] dark:shadow-gray-700`
  → `.cartoon-surface rounded-lg`. glass-ui ships exactly this Memphis
  offset-stamp recipe as `@utility cartoon-surface`
  (`cards.css:33-48`: `border-width: 2px; box-shadow:
  var(--shadow-cartoon-md)` + built-in hover-lift) backed by
  `--shadow-cartoon-md` (`tokens.css:558`), a theme-aware `light-dark()`-driven
  double-layer keyed off `--shadow-color`. The hand-rolled version uses a
  fixed black-opacity stamp, raw `border-gray-700` (not the resolved
  `--border`), and `dark:shadow-gray-700` as a band-aid for the white-on-dark
  stamp the token already solves. Drop `border-gray-700` and
  `dark:shadow-gray-700` entirely — `border-2` is already inside
  `cartoon-surface` and the dark behaviour comes from the token.
- **SquareScene halo** — `SquareScene.vue:38-53` defines a scoped `.square-box`
  whose every property is byte-for-byte the canonical `.demo-box`
  (`utils.css:101-114`) EXCEPT `:52` `box-shadow: 0 0 0 0.5rem rgba(255, 255,
  255, 0.5)` vs `.demo-box`'s `color-mix(in srgb, var(--background) 50%,
  transparent)`. The literal white halo is theme-blind (stays white in dark
  mode where `.demo-box` correctly tracks `--background` to a dark halo).
  Delete the entire scoped `<style>` block; set the element to `class="demo-box
  font-mono"` (or fold `font-family: var(--font-mono)` into `.demo-box` itself
  if it should serve every scene — its only real delta). Kills the duplicate,
  removes the only `rgba()` literal in `app/scenes/`, inherits dark-mode
  correctness for free.
- **EasingTarget global `.glass-card` leak** — `EasingTarget.vue:263` opens
  `<style>` (NOT `<style scoped>`, unlike sibling scenes), and `:267-270`
  declares `.glass-card { --track-ball-size-active: 36px; --track-ball-size-muted:
  24px; }` — injecting two component-private vars onto EVERY `.glass-card`
  in the app (8+ call sites). The JS at `:142` (`container.closest(".glass-card")`)
  is coupled to that leak. Give the component root (`:4`) a scoping handle —
  `class="glass-card easing-target ..."` — move the two vars onto
  `.easing-target` (a component-owned class), and retarget the JS to
  `container.closest(".easing-target")`. The tokens belong to the easing
  track, not the shared `.glass-card` primitive.

**WHY:** these are the three in-repo SHIP-now token transpositions the
color-token lens isolated (`design-findings.txt` color-token F1,F2,F3 [MED]):
one dedup against an existing utility, one utility adoption, one scoping fix —
all targets (`.demo-box`, `cartoon-surface`/`--shadow-cartoon-md`, `--border`)
already exist, so each is net-deletion with a dark-mode-correctness win
(the hard-white halo and the `dark:shadow-gray-700` patch both vanish once the
canonical tokens are adopted). The unscoped `.glass-card` override is an
anti-idiom (mutating a vendor utility from a component file) and a latent
global-namespace collision (component-idiom F2 [MED]).

### S4 — Define the undefined load-bearing layout tokens — layout-rhythm F2,F3,F6

**WHAT:** define/derive the three custom properties the demo's animations
depend on but that resolve to nothing today (verified dangling against demo
source AND glass-ui dist):
- **`--dock-menubar-reserve`** — consumed at `AnimationControlsGroup.vue:461`:
  `max-height: calc(100dvh - var(--dock-margin) - var(--dock-icon-height) -
  var(--dock-menubar-reserve))`. A `var()` with no fallback inside `calc()`
  makes the WHOLE `calc()` invalid → `max-height` falls back to `100dvh`/`none`,
  so the mobile controls pane claims full viewport height and its bottom
  content slides under the `AnimationMenuBar` (the controls-open mobile cramp).
  Add to `style.css` `:root` (where the layout tokens live, `:15-26`), derived
  from the SAME dock primitives as the top offset: `--dock-menubar-reserve:
  calc(var(--work-area-bottom-offset, 0px) + var(--dock-icon-height) +
  var(--dock-margin) + env(safe-area-inset-bottom, 0px))`. The bottom
  exclusion zone derives structurally (symmetry with `--work-area-top-offset`
  at `:25`), so the open pane can never tuck under the menubar.
- **`--spring-snappy`** — consumed at `AnimationControlsGroup.vue:509`:
  `transform var(--duration-slow) var(--spring-snappy)` on the open
  controls-pane. An undefined `transition-timing-function` makes the whole
  declaration invalid → the springy "slide in from left" degrades to default
  `ease`/no-transition, so the 400px pane pops rather than springs. Define it
  as a CSS `linear()` GENERATED by the engine the demo ships — emit
  `--spring-snappy: linear(...)` into `style.css` from `springLinearStops()`
  (`src/animation/index.ts:40`) seeded with the demo's own "Snappy" preset
  (`response: 0.35, dampingFraction: 0.65`). The demo's spring CSS is an output
  of the engine it demonstrates, not a hand-tuned cubic-bezier. (The exact
  engine wiring — generate-once at build vs a checked-in generated stop string
  — is shared with C.W3's dogfooding; W2 owns the token DEFINITION, W3 owns the
  rAF-loop transposition.)
- **`--work-area-vertical-bias` rationale** — `style.css:24-25`:
  `--work-area-vertical-bias: 4; --work-area-top-offset: max(calc((100dvh -
  --work-area-height) / 4), 0px)`. The comment claims a "¼ offset for balanced
  feel," but `slack/4` only biases meaningfully when `--work-area-height <
  100dvh` — on mobile (`--work-area-max-height: clamp(44rem, 94dvh, 64rem)`,
  `:61`) the slack is tiny so the bias is near-inert exactly where it's needed.
  Replace the magic divisor with an explicit optical-balance fraction: define
  `--work-area-top-offset` / `--work-area-bottom-offset` as an asymmetric pair
  (top:bottom ≈ 0.42:0.58 of slack) so the subject parks at the optical centre
  (slightly above geometric centre) consistently across viewports, documented
  as a ratio token, not a divisor.

**WHY:** these are dangling-token defects that silently break LIVE animation —
not cosmetics (`design-findings.txt` layout-rhythm F2 [HIGH], F3 [MED], F6
[LOW]). `--dock-menubar-reserve` is the controls-open mobile cramp the user
named; `--spring-snappy` is the broken desktop pane slide; the vertical-bias
is a token shaped like rhythm but functionally inert on the viewports that
need it. Deriving the reserve from the dock primitives (rather than
duplicating `--dock-margin + --dock-icon-height` inline) is the structural
home for one symmetric top/bottom exclusion-zone token pair — one source of
truth, not per-page constants.

## § Design decisions

1. **One display serif, formalized in the token — not a per-surface override.**
   RESOLVED (C.md §Resolved-design-decision 2): Instrument Serif is the demo's
   deliberate identity face, so it becomes `--font-display: "Instrument Serif"`
   — a single token decision in `style.css` `@theme`. Trade-off: the
   alternative (loading Fraunces, glass-ui's default display face) would add
   font payload and abandon the demo's existing character; formalizing
   Instrument Serif makes the ladder resolve correctly with ZERO new payload.
   The Fraunces `WONK`/`SOFT` axes no-op gracefully on the single-weight
   Instrument Serif, so the default `--font-display-weight: 400` is correct.

2. **Adoption, not re-authoring — the ladder is already imported.** Every φ
   utility the migration targets ships in
   `node_modules/@mkbabb/glass-ui/dist/styles/typography.css:152-351` and is
   already in the demo's import graph; `cartoon-surface` +
   `--shadow-cartoon-md`, `.demo-box`, `--border` likewise exist. So the wave
   writes essentially NO new CSS — it deletes the fork and consumes the
   canonical surfaces. Trade-off: the migration is per-element (no codemod can
   safely map `text-5xl` → the right register, because the correct register is
   semantic — title vs display vs heading — not size-mechanical), but that is
   the cost of riding the semantic ladder rather than a parallel numeric scale.

3. **The headline tier ships together; the leaf tail is BOOKED, not blocked.**
   RESOLVED: S1's display/heading/dock-label rows + S2 + S3 are the HEADLINE
   (fully visible in the home + easing captures) and ship as one change so the
   sweep (S5) bites on a complete surface. The ~128-site body/label leaf tail
   (F6) is a mechanical follow-on BOOKED with a real owner + trigger — so the
   headline is not gated on 128 leaf sites, and the deferral discipline §5
   demands (a real owner, not a phantom "next demo-touching wave") is honored.

4. **`--font-display` + `.instrument-serif` deletion land in the SAME change as
   S1.** RESOLVED: defining `--font-display` is the prerequisite (without it
   the migrated rungs render Georgia — F2 "must land in the same change"), and
   deleting `.instrument-serif` must follow the sweep that retires its 44 sites
   (a dangling alias is dead CSS, which the no-legacy mandate forbids). The
   ordering is: define the token → migrate the sites → delete the alias →
   sweep. No intermediate state ships a half-migrated alias.

5. **`--spring-snappy` is generated by the engine, not hand-tuned — W2 owns the
   token, W3 owns the loops.** RESOLVED: the demo's spring CSS is an OUTPUT of
   `springLinearStops()` (`src/animation/index.ts:40`), the same dogfooding
   root layout-rhythm F1/F3 share with the scene-swap. W2 owns the token
   DEFINITION (the `--spring-snappy: linear(...)` value in `style.css`); C.W3
   owns the rAF-loop transpositions. Trade-off: an interim
