# C.W4 — Engine residuals transposed (gestalt)

B.W2 transposed the engine's headline debt — one `RAFPlayback` driver, one
`withReducedMotion` gate, one rest-position contract, typed `Easing`, the
fail-explicit `parseOption` seam — and the re-audit confirms it as the model
(net deletion, no alias, the WAAPI css-twin gate *correct*). What the
16-finding review left are the contract-EDGES the unification papered over:
a sibling driver method that never got the generation guard its twin did, a
`tick`/`tickDt` surface that means four different things, two setters that
quietly bypass the fail-explicit contract, a default easing with no
compositor path, and a boundary gate with residual false-negative classes +
an undeclared dependency. W4 finishes the unification — each item a
transposition that DELETES divergence, not a patch. Grounds:
`audit/plan-findings.txt` (engine-fidelity [MED]×3/[LOW]×2, boundary-ci
[MED]×2/[LOW]×5, deferred-ledger [MED]).

## § Goal

The engine's transposition is COMPLETE to its edges: one generation-guarded
loop core, one canonical step method, one fail-explicit setter surface, a
default easing that runs faithfully on the compositor, and a boundary gate
with no residual false-negative class and no undeclared dependency. Every
change deletes more than it adds; no new workaround, legacy path, or alias.

## § Scope

### S1 — `RAFPlayback.drive` gets the generation guard — fold `drive`/`loop` to one core

**What:** `loop()` was hardened with a `_gen` counter so a `stop()`+restart
mid-async-frame cannot re-arm a second rAF chain (`playback.ts:73,168-187`,
landed in `7fc60e5`). Its sibling `drive()` (`playback.ts:142-159`) never got
it — it guards only on `_rafId !== null`, so a consumer-supplied
`onFrame`/`tickDt` that re-enters `setTarget`→`_startLoop`→`drive`
synchronously can schedule on top of a freshly-repopulated `_rafId`
(engine-fidelity [MED]). The gestalt is NOT to copy the guard into `drive` —
it is to recognize that `play` (= `loop` + a clock + the reduced-motion
gate), `drive` (= `loop` + a settle-check), and `loop` are ONE primitive with
three thin entry shapes. Fold them into a single generation-guarded
frame-scheduler core; the three public methods become parameterizations.
**Why:** the three-method split is what let `drive` diverge and miss the
guard. One guarded core cannot have an unguarded sibling — the divergence is
deleted at the root, not patched per method.

### S2 — One canonical `tickDt(dt: ms)` step across every stepper

**What:** `tick`/`tickDt`/`tick(dt)` mean four different things —
`SmoothProgress.tick()` takes no arg (frame-dependent, `smooth.ts:106`),
`SpringProgress.tick(dt)` takes SECONDS (`spring.ts:204`), `*.tickDt(dt)`
takes MS, `Timeline.tick()` takes none — so `obj.tick(16)` means "advance 16
seconds" on a spring but "advance one damping step, arg ignored" on a
smoother, a polymorphism foot-gun the `Tickable` interface only half-resolved
(it standardizes `tickDt` but the public `tick` surface stays incoherent;
`Tickable.tickDt` is even typed `:void` while implementors return `number`).
Make `tickDt(dt: ms): number` the SINGLE canonical, public step on every
stepper; demote `SmoothProgress.tick()` and `SpringProgress.tick(seconds)` to
private internals (or delete — the internal callers `springLinearStops.ts:64`
+ `springTimingFunction.ts:88` adapt to `tickDt(dt*1000)` or a private
`_stepSeconds`); fix `Tickable.tickDt` to `:number`. **Why:** one step, one
unit, across all four steppers — the unification the `Tickable` interface
implied but did not finish. A consumer can finally treat the steppers
polymorphically without a units foot-gun.

### S3 — `setColorSpace` + `setHueMethod` join the fail-explicit seam

**What:** the fail-explicit contract (`errors.ts`, the nine setters at
`engine.ts:488-655`) is "present-but-malformed THROWS `AnimationOptionError`;
only genuine `undefined` defaults." But `setColorSpace` (`engine.ts:657-662`)
does `colorSpace ?? defaultOptions.colorSpace` — a malformed present value
(`setColorSpace("srgbbb")`) is accepted and written, no throw; `setHueMethod`
(`engine.ts:664-669`) writes any non-`undefined` value unchecked
(engine-fidelity [MED]). Route both through `parseOption` against value.js's
`ColorSpace`/`HueInterpolationMethod` unions, throwing `AnimationOptionError`
on a malformed present value. **Why:** the two setters that bypass the seam
are the contract half-honored; closing them makes the fail-explicit invariant
total, not "nine of eleven."

### S4 — The default easing gets a `cubic-bezier()` css-twin (faithful default compositor path)

**What:** `defaultOptions.timingFunction = { fn: easeInOutCubic }` carries no
`.css` (`constants.ts:156`), and `cssTwinFor` returns `undefined` for all
value.js bespoke names — so the css-twin WAAPI gate (CORRECTLY) keeps every
DEFAULT-eased animation on rAF; the *default* surface has no compositor path
at all (engine-fidelity [INFO], the named perf lever). Ship
`defaultOptions.timingFunction = { fn: easeInOutCubic, css: "cubic-bezier(0.645,0.045,0.355,1)" }`
— the standard easeInOutCubic bezier approximation — so the default surface
moves back onto the compositor FAITHFULLY (the curve round-trips to CSS), with
ZERO gate changes. **Why:** one constant change is the entire default-surface
perf lever. It MUST be verified first: assert the sampled `cubic-bezier(...)`
curve matches `easeInOutCubic` within tolerance across [0,1] (a test), so the
compositor runs the same curve rAF would — no silent visual drift. If the
fidelity check fails at the required tolerance, the default stays rAF-only and
the finding is RECORDED (no approximation shipped that isn't faithful).

### S5 — `Timeline._advance` deduplication

**What:** `Timeline._advance` (`timeline.ts`) duplicates the
`smoother.setTarget` call and splits the smoother-drive logic awkwardly across
two branches (engine-fidelity [LOW]). Collapse to one `setTarget` + one
branch on the time-step variant. **Why:** a small structural duplication; the
no-duplication discipline applies at every scale.

### S6 — `proof:boundary` residual false-negatives + declare `rolldown` + pin glass-ui

**What:** the boundary gate has residual false-negative classes (boundary-ci
[LOW]×5): assertion 1 does not catch a live bare side-effect
`import "@mkbabb/value.js"` (tree-shaken before the bundle-graph count sees
it — the source-grep must catch it, and currently the bare form is sealed only
by assertion 4's regex which ALSO misses subpath specifiers
`@mkbabb/value.js/...`); assertion 2's self-enforcing entry set only covers
`export {…} from` (a direct `export const`/`function` light export drifts
unproven); assertion 4's HEAVY allowlist is a hardcoded basename set
(rename-fragile, dir-blind). Close each. Plus: `rolldown` is an UNDECLARED
load-bearing dependency of the gate (boundary-ci [MED]) — declare it in
`devDependencies`. Plus: the CI demo gate clones glass-ui's DEFAULT branch
with no pin (boundary-ci [MED], genuinely fragile — a glass-ui main break
reds keyframes CI); PIN to a tag/commit, or vendor a built glass-ui, so the
demo gate is reproducible. **Why:** a gate with a false-negative class is a
gate that asserts more than it proves; an undeclared gate dependency is a gate
that can vanish; an unpinned moving-target clone is a gate that flakes on a
foreign repo's HEAD. inv α + the demo gate become airtight + reproducible.

### S7 — `dev.sh` / `deploy.sh` — land or KILL (no third punt)

**What:** the `dev.sh`/`deploy.sh` library-shape adoption was booked A.W0 →
B.W6 and never landed (deferred-ledger [MED], twice-booked). Either land
`scripts/deploy.sh` (the drafted gh-pages-on-master / npm-on-tag wrapper whose
`do_build` routes through `build:lib` per inv β) + `scripts/dev.sh`, OR KILL
with a recorded rationale (the demo deploy is a dev-machine concern; CI
already gates the build). **Why:** a twice-booked item is one cycle from a
perpetual punt; C makes the terminal call.

## § Hard gate

- **One loop core, generation-guarded.** A focused test proves a
  `stop()`+restart mid-frame on `drive` (via a re-entrant `onFrame`) spawns
  NO second rAF chain (the same bite `loop`'s guard has). `grep` confirms
  `drive`/`loop`/`play` share one guarded primitive, not three.
- **One step method.** Every stepper's public step is `tickDt(dt: ms): number`;
  the divergent `tick()`/`tick(seconds)` are private/gone; `Tickable.tickDt`
  is `:number`. A test asserts `tickDt(16)` advances the same physical amount
  on smooth + spring (no units foot-gun).
- **Fail-explicit total.** `setColorSpace("bogus")` and `setHueMethod("bogus")`
  THROW `AnimationOptionError` (a test); genuine omission still defaults.
- **Default compositor path faithful.** The default easing carries its css
  twin AND a test asserts the bezier matches `easeInOutCubic` within
  tolerance across [0,1]; an `isWAAPIEligible` test shows a default-eased
  animation is now eligible.
- **Boundary airtight.** Each residual false-negative turns the gate RED when
  introduced (bare import, subpath specifier, `export const` light export);
  `rolldown` is in `devDependencies`; the CI demo gate references a PINNED
  glass-ui. `proof:boundary` + the full chain stay green.
- **Net deletion.** `git diff --shortstat` for W4 shows more deleted than
  added; no alias, no legacy path introduced.

## § Design decisions

1. **Fold, don't copy the guard.** RESOLVED: `drive` missing the guard is a
   SYMPTOM of the three-method split; the fix is one guarded core, not a
   third copy of the `_gen` dance. The transposition deletes the divergence.
2. **One unit, ms.** RESOLVED: `tickDt(ms)` is canonical because rAF deals in
   ms and the driver already steps in ms; the seconds-based `SpringProgress.tick`
   becomes an internal adapter. No public method takes seconds.
3. **Verify the css-twin before shipping it.** RESOLVED: the default bezier
   ships ONLY if it matches `easeInOutCubic` within tolerance — a faithful
   compositor curve or none. No approximation that drifts is shipped (the
   css-twin gate exists precisely to keep the compositor faithful).
4. **Pin the CI demo gate.** RESOLVED: cloning a foreign repo's moving HEAD in
   keyframes CI is a reproducibility hole; pin glass-ui to a known-good ref so
   a glass-ui main break cannot red keyframes CI for an unrelated reason.
