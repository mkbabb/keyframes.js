## § Design decisions

1. **inv ε is verified, not asserted.** RESOLVED: every gate FINAL claims MET
   carries the checked-in instrument's passing run as its evidence. The whole
   reason C exists is that B asserted gates without re-running them; W5's
   FINAL cannot repeat that.
2. **AFTER captures the W4-repaired build via the CHECKED-IN harness.**
   RESOLVED: the harness is now `scripts/capture.mjs` (C.W0), so "re-runs
   identically" is true — the before/after is a real diff of one instrument
   across time, not two shoots.
3. **One release ships B + C.** RESOLVED: the B 3.1.0 changeset was cut but
   never published; folding it into C's changeset ships both tranches in one
   provenance-signed publish, so the engine transposition (B) + the close-
   honesty/design/dogfood (C) reach consumers together.
4. **The bump tier turns on the `tick` canonicalization.** RESOLVED: demoting
   the divergent public `tick` variants (W4 S2) is a breaking surface change →
   **major**; named here so the publish leg is not orphaned and the SemVer is
   honest (no silent breaking change under a minor).
5. **The publish leg is user-domain, confirm-first — IDENTICAL to A/B.**
   RESOLVED: W5 authors the changeset and stages the leg; the outward push
   runs only on explicit user authorization. The provenance path
   (`id-token: write` + `--provenance`) is the standing publish path A made
   canonical; C reuses it unchanged.
