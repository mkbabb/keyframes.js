2. **[MED — lifecycle gap the 16-finding review missed] `RAFPlayback.drive()` has no generation guard — the exact double-schedule class `loop()` was hardened against.** The review fixed `loop()` with a `_gen` counter so a `stop()`+restart mid-async-frame cannot re-arm a second rAF chain (`playback.ts:73, 168-187`, called out in commit `7fc60e5`). But `drive()` (`playback.ts:142-159`) uses only the `if (this._rafId !== null) return` idempotency guard and never touches `_gen`. `drive`'s `frame` callback is *synchronous* (no `await`), so the in-flight-async-frame race that bit `loop` cannot occur identically — **but** the asymmetry is a latent trap: `drive`'s guard is `_rafId !== null`, and `stop()` bumps `_gen` + nulls `_rafId`, so a `frame` that has *already captured* its closure and is executing when `stop()`+`drive()` interleave (possible if a `tickDt` or `onFrame` callback re-enters `setTarget`→`_startLoop`→`drive` synchronously) will see `_rafId` freshly repopulated by the restart and schedule on top of it. Spring/smooth `_onFrame` callbacks are consumer-supplied and *can* re-enter. **Disposition: BOOK.** **GESTALT fix:** give `drive` the same `_gen`-captured reschedule check `loop` has (`const gen = ++this._gen; … if (gen !== this._gen) return;`), or — cleaner — fold `drive` and `loop` into one generation-guarded primitive since both are "schedule frame, conditionally reschedule." The three-method split (`play`/`drive`/`loop`) is itself slightly over-shaped; `play` is `loop` + a clock + the reduced-motion gate, `drive` is `loop` + a settle-check. One guarded core with three thin entry shapes would delete the divergence that let `drive` miss the guard.

3. **[MED — naming incoherence the `Tickable` unification hid] `tick` / `tickDt` / `tick(dt)` mean four different things across the light steppers; the `Tickable` interface unifies only `tickDt`.** `SmoothProgress.tick(): number` takes no arg (frame-rate-*dependent*, fixed damping, `smooth.ts:106`); `SmoothProgress.tickDt(dt): number` takes **ms** (`smooth.ts:128`); `SpringProgress.tick(dt): number` takes **seconds** (`spring.ts:204`); `SpringProgress.tickDt(dt): number` takes **ms** (`spring.ts:221`, a units adapter over `tick`); `Timeline.tick()` takes none (`timeline.ts:129`). So `obj.tick(16)` means "advance 16 seconds" on a spring but "advance one damping step, arg ignored" on a smoother — a foot-gun for a consumer treating them polymorphically.
