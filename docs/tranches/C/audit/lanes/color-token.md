# Tranche-C Color + Tokens Audit (Lane: frontend-design / COLOR + TOKENS)

The demo is ~95% token-faithful; the remaining off-token literals are concentrated in four files. The highest-value finding is that `SquareScene.vue` re-hand-rolls a utility (`.demo-box`) that **already exists token-correct** in the repo — a pure dedup with a dark-mode-correctness win. All glass-ui token names below were verified against `node_modules/@mkbabb/glass-ui/dist/styles/{tokens,cards}.css`.

---

1. **[medium] SquareScene `.square-box` is a verbatim fork of the existing `.demo-box` utility, with the halo regressed to a hard-white `rgba`** — `demo/app/scenes/SquareScene.vue:38-53` defines a scoped `.square-box` whose every property (`--size:12rem`, flex-center, `border-radius:var(--radius-lg)`, `font-size:var(--type-body)`, `background-color:aquamarine`) is byte-for-byte identical to the canonical `.demo-box` in `demo/@/styles/utils.css:101-114` — **except** line 52: `box-shadow: 0 0 0 0.5rem rgba(255, 255, 255, 0.5)` vs `.demo-box`'s `box-shadow: 0 0 0 0.5rem color-mix(in srgb, var(--background) 50%, transparent)` (utils.css:113). The literal white halo is theme-blind: it stays white in dark mode where `.demo-box` correctly tracks `--background` to a dark halo. (SquareScene's extra `font-family:var(--font-mono)` is the only real delta.) — **disposition: SHIP** — **gestalt fix:** delete the entire scoped `<style>` block and the `square-box` class; set the element to `class="square-box"` → `class="demo-box font-mono"` (or, if `font-mono` should be the demo default, fold `font-family: var(--font-mono)` into `.demo-box` itself so it serves every scene). This kills the duplicate, removes the only `rgba()` literal in `app/scenes/`, and inherits dark-mode correctness for free.

2. **[medium] CSSCodeEditor cartoon-stamp shadow + border are fully hand-rolled, bypassing the `cartoon-surface` utility** — `demo/@/components/custom/animation-controls/keyframes/CSSCodeEditor.vue:6`: `border ? 'border-2 border-gray-700 shadow-[4px_4px_0px_0px_rgba(0,0,0,0.6)] dark:shadow-gray-700'`. This is the Memphis offset-stamp register, which glass-ui ships as `@utility cartoon-surface` (`cards.css:33-48`): `border-width:2px; box-shadow:var(--shadow-cartoon-md)` plus a built-in `translate`+hover-lift. The hand-rolled version (a) uses a fixed `+4px/+4px` black-opacity stamp where the token `--shadow-cartoon-md` is a theme-aware, light-dark()-driven double-layer (`tokens.css:558`, `1478-1479`); (b) uses `border-gray-700` (a raw Tailwind gray) instead of the resolved `--border`; (c) the `dark:shadow-gray-700` patch is a band-aid for the white-on-dark stamp that the token already solves via `--shadow-color`. — **disposition: SHIP** — **gestalt fix:** replace the whole conditional string with `border ? 'cartoon-surface rounded-lg' : ''`. The `border-2` is already inside `cartoon-surface`, the stamp and its dark-mode behavior come from `--shadow-cartoon-md`, the border tone resolves from `--border`, and you also gain the canonical hover-lift. Drop `border-gray-700` and `dark:shadow-gray-700` entirely.

3. **[medium] EasingTarget injects component-private vars onto the GLOBAL `.glass-card` selector via an UNSCOPED `<style>` block** — `demo/easing/EasingTarget.vue:263` opens `<style>` (no `scoped` attribute, unlike sibling scenes), and lines 267-270 declare `.glass-card { --track-ball-size-active:36px; --track-ball-size-muted:24px; }`. This leaks the two track-ball vars onto **every** `.glass-card` in the document — and the JS at line 142 (`container.closest(".glass-card")`) is coupled to that leak, reading the vars off whatever ancestor card happens to match. These vars are private to EasingTarget's comparison track; nothing else should carry them. The rest of that style block (`.track-*`, `.t-scrubber`) is correctly token-driven (`--color-progress`, `color-mix(... var(--color-progress) ...)`), so the bug is narrowly the unscoped `.glass-card` override + global emission. — **disposition: SHIP** — **gestalt fix:** give the component's root `.glass-card` (template line 4) a scoping handle, e.g. `class="glass-card easing-target ..."`, move the two vars onto `.easing-target` (a component-owned class, not the shared `.glass-card` token surface), and retarget the JS to `container.closest(".easing-target")`. If the block must stay in this file, mark it `<style scoped>` and bind the vars to the root via `:where()` so they cannot escape the component subtree.

4. **[low] KeyframesEditor rainbow progress-bar gradient has one off-token literal cyan stop** — `demo/@/components/custom/animation-controls/keyframes/KeyframesEditor.vue:476-485`: the `linear-gradient` reads `--rainbow-red/yellow/green/blue/violet` for six of seven stops, but the 50% stop is hard-coded `hsl(180 80% 50%)` (KeyframesEditor.vue:481). glass-ui defines `--rainbow-{red,orange,yellow,green,blue,indigo,violet}` (`tokens.css:1026-1032`) but **no `--rainbow-cyan`** — the literal is patching a genuine palette gap, not laziness. — **disposition: BOOK** (cross-repo) — **gestalt fix:** add `--rainbow-cyan` to the glass-ui rainbow scale in the glass-ui repo (per MEMORY: glass-ui token changes never patched in demo), then swap the stop to `var(--rainbow-cyan) 50%`. This completes the spectral ramp as a real token and removes the last `hsl()` literal in the controls suite.

5. **[low/RECORD] Cube + Square ANIMATED palettes are intentional content payload, not chrome — do not tokenize** — `demo/cube/CubeTarget.vue:118-125` (`rgba(255,0,0,0.8)` … `rgba(0,255,255,0.8)`, the six pure-channel face colors) and `demo/square/useSquareAnimations.ts:51-63` (`#C462D8`, `#6280D8`, `#52E898`, `#E85252`, the interpolated keyframe stops) are the **subject matter** of these demos: the cube shows the six primaries/secondaries on its faces, and the square's whole purpose is to demonstrate perceptual color interpolation between four arbitrary hues. Forcing these onto glass-ui chrome tokens (`--chart-*`, `--accent-*`) would defeat the demonstration and couple demo data to design-system semantics. The `aquamarine` rest-state in `.demo-box` (utils.css:112) is similarly a deliberate "before-animation" payload color. — **disposition: RECORD (intentional, KILL any tokenization ask)** — **gestalt note:** leave as data literals; if a future ask wants them centralized, lift them into a local `cubeFaceColors` / `squarePalette` constant in the demo's own `*.ts` (a data module), NOT into glass-ui tokens — they are content, not design tokens.
