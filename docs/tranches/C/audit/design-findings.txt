I have a complete, exhaustive picture of my lane. The demo's glass-ui consumption is strongly idiomatic with a few localized, already-deferred off-token sites. Here is my report.

**Summary:** The keyframes.js demo consumes glass-ui idiomatically at the structural level — dock, cards, dialog, slider, status-dot, glass-panel, type/shadow tokens, and the `.glass-card`/`.btn-interactive`/`.cartoon-surface` utility families are all real glass-ui exports correctly adopted, and the demo deeply dogfoods the keyframes.js engine (Animation, AnimationGroup, NumericAnimation, SpringProgress, springLinearStops, springTimingFunction, presets). 1. **[low] One redundant hand-rolled blur masks glass-ui's own Dialog glass tier** — `demo/@/components/custom/KeyboardShortcutsModal.vue:3` sets `<DialogContent class="max-w-md backdrop-blur-sm">`. glass-ui's `DialogContent.vue:78` already composes `.glass-floating` (the floating glass tier with its own blur/shadow) by default, and `DialogContent.vue:112-117` already mounts a `<ModalOverlay scrim="glass">`. The demo's `backdrop-blur-sm` double-stacks a second, weaker blur on a surface glass-ui already glassed — the *only* hand-rolled glassmorphism in the entire demo source (grep `backdrop-filter|backdrop-blur` = this single hit). — **SHIP** (delete the class) — GESTALT fix: remove `backdrop-blur-sm` entirely and let `DialogContent`'s default `glass-floating` variant own the blur; if a tighter blur is the intent, pass it through the component's `variant` prop, not an ad-hoc Tailwind utility on the wrapper. Do not re-blur a surface glass-ui already glasses.

2. **[medium] `.glass-card` override in EasingTarget is global-scope — leaks `--track-ball-size-*` vars onto every glass-card app-wide** — `demo/easing/EasingTarget.vue:263` opens `<style>` (NOT `<style scoped>`), and line 267 declares `.glass-card { --track-ball-size-active: 36px; --track-ball-size-muted: 24px; }`. Harmless today only because no other surface reads those vars, but it is a latent global-namespace collision and an anti-idiom (mutating a vendor utility class from a component file). — **BOOK** — GESTALT fix: scope the override to the component's own root, not the shared utility. Either add `scoped` to the style block and target a component-local class (e.g. `.easing-target`), or define the track tokens on the EasingTarget root element directly (`<div class="glass-card easing-track-host">` + `.easing-track-host { --track-ball-size-active: ... }`). The tokens belong to the easing track, not to the glass-card primitive.

# Tranche-C Lane Report — TYPOGRAPHY + the φ-ladder (C's HEADLINE)

**Summary:** The demo runs an entirely ad-hoc raw-Tailwind type scale (267 raw-rung occurrences across `text-8xl`…`text-xs`) bolted to a single hand-rolled `.instrument-serif` alias (44 source sites / 20 files) — there is no semantic ladder, no display register, and the hero h1 (B.W5's deferred headline) is `text-6xl/lg:text-8xl` on Instrument-Serif-as-body. glass-ui already ships the complete φ-ladder (`--type-*` √φ scale + `@utility text-display-*/text-heading/text-title/text-subheading/text-prose/text-body/text-admin-label/dock-label`) the demo imports but never adopts. The GESTALT move: formalize **one display serif** in `--font-display` (Instrument Serif, the demo's existing voice) and migrate every raw rung onto the semantic ladder, retiring `.instrument-serif`.

## Findings

### 1. **[high] The hero h1 is raw `text-6xl/text-8xl` — C's deferred HEADLINE has no semantic register**
Evidence: `demo/@/components/custom/editor-shell/EditorStartScreen.vue:6` — `class="instrument-serif grid p-0 text-6xl lg:flex lg:text-8xl"`; subtitle h2 at `:22` is `instrument-serif w-full text-5xl font-light italic`; hint h2 at `:28` is `instrument-serif w-full text-2xl font-light italic opacity-50`. Confirmed in `after/home-desktop.png`: "Select an animation" renders as the page's dominant glyph mass at top-left, but it's an arbitrary `text-8xl` (6rem, no clamp) on the body serif — no fluid clamp, no `text-wrap: balance`, no display weight/axis. glass-ui's display rungs ARE clamp-fluid + balanced (typography.css:111-264). This is the single most load-bearing type decision in the product and it currently sits on the raw scale.
Disposition: **SHIP** (this is C's headline; ship the migration as the centerpiece).
GESTALT fix: hero h1 → `.text-display-3` (φ^3, clamp 2.618→4.236rem) or `.text-display-4` (φ^(7/2), clamp 3.33→5.382rem) for full poster presence; both carry `text-wrap: balance`, `--type-tracking-tight`, `--type-leading-display` for free. Drop `text-6xl lg:text-8xl` entirely — the clamp replaces the `lg:` breakpoint hop. Keep the orthogonal `.depth-text` (glass-ui) + `AnimatedText` stagger — they compose cleanly with the type class.

### 2. **[high] `--font-display` is never defined in the demo — every display rung silently falls to Georgia**
Evidence: `demo/@/styles/style.css:7` defines only `--font-serif: "Instrument Serif", Georgia, serif`; grep for `--font-display` in demo source returns ZERO definitions (the lone hit at `AssetViewport.vue:52` merely *reads* `var(--font-display)` for an asset default). glass-ui's `text-display-*`/`text-title`/`text-heading` all resolve `font-family: var(--font-display)` (typography.css:153,191,257,271,280) which defaults to Fraunces — **a face the demo never loads** (`demo/*/index.html` load only Instrument Serif + self-hosted Fira Code; no Fraunces, no glass-ui `styles/fonts` import). So adopting the ladder naively would render the hero in Georgia.
Disposition: **SHIP** (prerequisite for the whole migration — must land in the same change).
GESTALT fix: in `style.css` `@theme` block (alongside `--font-serif`), add `--font-display: "Instrument Serif", Georgia, serif;` — formalizing the demo's existing single display serif as the display voice. Instrument Serif IS the demo's character (per `after/home-desktop.png`); this makes the ladder resolve correctly with zero new font payload. Optionally set `--font-display-weight` to taste (Instrument Serif is single-weight ~400, so the default 400 is correct; no `WONK/SOFT` axes — they no-op gracefully on a non-Fraunces face).

### 3. **[high] `.instrument-serif` (44 sites/20 files) is a redundant hand alias the φ-ladder subsumes**
Evidence: defined at `demo/@/styles/utils.css:84` as `{ font-family: var(--font-serif); letter-spacing: 0.02em; }`. It re-implements what glass-ui's serif classes already encode (font-family + tracking), forcing every site to *also* hand-pick a raw rung (`instrument-serif text-xl`, `instrument-serif text-lg`, `instrument-serif text-sm`, etc.). It's a font-family band-aid because the demo never adopted the semantic classes. Note `AnimationMenuBar.vue:118` even stacks all three: `dock-label instrument-serif text-lg` — a tell that the alias and the rung and the dock register are all fighting over the same element.
Disposition: **KILL** (`.instrument-serif` is legacy by the MANDATE; remove the alias, migrate all sites).
GESTALT fix: delete `.instrument-serif` from utils.css; replace every `instrument-serif text-N` pair with the single semantic class that already bundles font + size + line-height + tracking + weight (mapping table below). The `0.02em` tracking baked into the alias is design noise — the ladder's per-register `--type-tracking-*` is the correct, intentional tracking.

### 4. **[med] 267 raw rungs across 8 distinct sizes = an undocumented parallel scale fighting the φ-ladder**
Evidence (source-only counts): `text-8xl`×1, `text-6xl`×1, `text-5xl`×3, `text-3xl`×2, `text-2xl`×5, `text-xl`×8, `text-lg`×11, plus `text-base`/`text-sm`/`text-xs` at body/label scale. These are Tailwind's default 1.25-ratio steps — they do NOT align to glass-ui's √φ (1.272) ladder, so the demo's headings and the glass-ui components it embeds (dock, cards, popovers) sit on two incommensurate scales. Visible in `after/easing-desktop.png`: the "Easing Preview" dock label, "Singular" mode label, and `f(t)`/`1`/`t` axis glyphs are all separately sized rather than drawn from one register set.
Disposition: **SHIP** (migrate wholesale).
GESTALT fix: the class-by-class mapping table below. Net effect: 8 raw sizes collapse to ~6 semantic registers, all on the √φ ladder, all inheriting correct line-height/tracking/weight/balance.

### 5. **[med] Dock labels use `text-xl`/`text-lg` raw, ignoring glass-ui's purpose-built `dock-label` register**
Evidence: `TopDock.vue:146,151,172,178,214` and `AnimationMenuBar.vue:33,43,118,124` size dock-pill labels (Controls/Scene/Timeline triggers, selected-animation name) with raw `instrument-serif text-lg`/`text-xl`. glass-ui CHANGELOG:2023-2030 documents the exact precedent: `.text-heading` reads as literal bold inside a dock pill, so `dock-label` (weight 400, `--type-subheading` size, `--font-display` pinned) was created specifically for "text labels INSIDE dock-tab-button (Start, Next, Submit, …)" (typography.css:295-308). The demo already half-knows this — `AnimationMenuBar.vue:118` applies `dock-label` then *overrides* it with `instrument-serif text-lg`.
Disposition: **SHIP** (adopt `dock-label` cleanly; remove the override stack).
GESTALT fix: dock trigger/label spans → bare `.dock-label` (drop the `instrument-serif text-lg/text-xl`). It pins `--font-display` (now = Instrument Serif per Finding 2) and sizes to `--type-subheading` (√φ rung, 1.272rem). For dock-internal selected-animation names that need emphasis, `.dock-label font-semibold` is the idiomatic composition.

### 6. **[low] Body/label/caption raw rungs (`text-base`/`text-sm`/`text-xs` on `.instrument-serif`) should map to `text-body`/`text-small`/`text-caption`/`text-admin-label`**
Evidence: `text-sm`×49 (23 files), `text-xs`×79 (20 files), `text-base`×28; on `.instrument-serif` specifically: `AnimationControlsGroup.vue:247` (`text-base` ribbon buttons), `PlaybackRibbon.vue:36` (`text-base`), `LayerConfigPanel.vue:15` (`text-base`), `EasingSidebar.vue:38,49,74` + `SpringSidebar.vue:8,25,62,84` + `EasingSelect.vue:33` (`text-xs` muted labels), `KeyframeTimeline.vue:45,73` (`text-sm`). The `text-xs text-muted-foreground` uppercase-ish parameter labels (`steps`, `jump`, `response`, `dampingFraction`) are exactly the `text-admin-label` register (mono, 10px, uppercase, caps tracking) — currently they're serif lowercase, an inconsistency with glass-ui's control-panel idiom.
Disposition: **BOOK** (lower-stakes long tail; book as a follow-on sweep so C's headline ships clean, not blocked on 156 leaf sites).
GESTALT fix: `text-base`→`.text-body`; `text-sm`→`.text-small`; `text-xs` muted control labels→`.text-admin-label` (or `.text-mono-caption` if uppercase reads too loud); `text-caption` for italic captions. The "or drag M. cubert" sub-hint in `after/home-desktop.png` → `.text-caption` (serif italic, already its visual treatment).

# Tranche-C Color + Tokens Audit (Lane: frontend-design / COLOR + TOKENS)

The demo is ~95% token-faithful; the remaining off-token literals are concentrated in four files. The highest-value finding is that `SquareScene.vue` re-hand-rolls a utility (`.demo-box`) that **already exists token-correct** in the repo — a pure dedup with a dark-mode-correctness win. All glass-ui token names below were verified against `node_modules/@mkbabb/glass-ui/dist/styles/{tokens,cards}.css`.

---

1. **[medium] SquareScene `.square-box` is a verbatim fork of the existing `.demo-box` utility, with the halo regressed to a hard-white `rgba`** — `demo/app/scenes/SquareScene.vue:38-53` defines a scoped `.square-box` whose every property (`--size:12rem`, flex-center, `border-radius:var(--radius-lg)`, `font-size:var(--type-body)`, `background-color:aquamarine`) is byte-for-byte identical to the canonical `.demo-box` in `demo/@/styles/utils.css:101-114` — **except** line 52: `box-shadow: 0 0 0 0.5rem rgba(255, 255, 255, 0.5)` vs `.demo-box`'s `box-shadow: 0 0 0 0.5rem color-mix(in srgb, var(--background) 50%, transparent)` (utils.css:113). The literal white halo is theme-blind: it stays white in dark mode where `.demo-box` correctly tracks `--background` to a dark halo. (SquareScene's extra `font-family:var(--font-mono)` is the only real delta.) — **disposition: SHIP** — **gestalt fix:** delete the entire scoped `<style>` block and the `square-box` class; set the element to `class="square-box"` → `class="demo-box font-mono"` (or, if `font-mono` should be the demo default, fold `font-family: var(--font-mono)` into `.demo-box` itself so it serves every scene). This kills the duplicate, removes the only `rgba()` literal in `app/scenes/`, and inherits dark-mode correctness for free.

2. **[medium] CSSCodeEditor cartoon-stamp shadow + border are fully hand-rolled, bypassing the `cartoon-surface` utility** — `demo/@/components/custom/animation-controls/keyframes/CSSCodeEditor.vue:6`: `border ? 'border-2 border-gray-700 shadow-[4px_4px_0px_0px_rgba(0,0,0,0.6)] dark:shadow-gray-700'`. This is the Memphis offset-stamp register, which glass-ui ships as `@utility cartoon-surface` (`cards.css:33-48`): `border-width:2px; box-shadow:var(--shadow-cartoon-md)` plus a built-in `translate`+hover-lift. The hand-rolled version (a) uses a fixed `+4px/+4px` black-opacity stamp where the token `--shadow-cartoon-md` is a theme-aware, light-dark()-driven double-layer (`tokens.css:558`, `1478-1479`); (b) uses `border-gray-700` (a raw Tailwind gray) instead of the resolved `--border`; (c) the `dark:shadow-gray-700` patch is a band-aid for the white-on-dark stamp that the token already solves via `--shadow-color`. — **disposition: SHIP** — **gestalt fix:** replace the whole conditional string with `border ? 'cartoon-surface rounded-lg' : ''`. The `border-2` is already inside `cartoon-surface`, the stamp and its dark-mode behavior come from `--shadow-cartoon-md`, the border tone resolves from `--border`, and you also gain the canonical hover-lift. Drop `border-gray-700` and `dark:shadow-gray-700` entirely.

3. **[medium] EasingTarget injects component-private vars onto the GLOBAL `.glass-card` selector via an UNSCOPED `<style>` block** — `demo/easing/EasingTarget.vue:263` opens `<style>` (no `scoped` attribute, unlike sibling scenes), and lines 267-270 declare `.glass-card { --track-ball-size-active:36px; --track-ball-size-muted:24px; }`. # Tranche-C a11y/responsive close — frontend-design lane findings

**Summary:** B's W5 self-certified "lighthouse A11y closed" against the *panel-closed start screen* only; the moment a controls panel is open — the actual editing UI, auto-opened on amiga/square/easing — A11y collapses to **75–79** (`button-name`, `label`, `aria-input-field-name`, `color-contrast`), and even the "closed" `landmark-one-main` is still failing because the `<main>` B added carries `display:contents`, which elides its landmark role. The root of the three input-naming fails is a single structural defect in glass-ui's `LabeledField` family (label rendered with no `for`/`id`/`aria-labelledby` association) — one outward fix closes them everywhere. Evidence is the post-W5 prod run at `docs/tranches/B/audit/lighthouse/after-prod/_summary.json` (fetchTime 2026-06-04).

---

### 1. **[critical] `landmark-one-main` is still failing on every page — `display:contents` strips the `<main>` role** — disposition: SHIP (demo-owned)
`demo/@/components/custom/editor-shell/EditorShell.vue:36` adds `<main class="contents" aria-label="Animation editor">`. `class="contents"` → `display:contents`, which removes the element's box **and its implicit `main` landmark from the accessibility tree** in Chromium. The after-prod lighthouse JSON flags `landmark-one-main` on *all* pages with the offending node `<html>` ("no main landmark found at all") at `after-prod/home-mobile.json` (score 0, fetchTime 2026-06-04T17:05Z) — i.e. the very landmark W5 added is invisible to a11y. B.W5/FINAL.md:17 marks this "✅ MET / `<main>`=1", which is **false in the rendered a11y tree**.
**Gestalt fix:** Stop fighting the grid with `display:contents`. Promote `<main>` to the actual layout element — make the AnimationControlsGroup's own root the `<main>` (render-as / `:is="'main'"`), or wrap with `class="contents"` replaced by a real grid participant that occupies the same cell (`grid-area`/`place-self` instead of contents). The landmark must be a layout-box-bearing element so its role survives. One element, one role, no `aria-label` band-aid needed (a sole `<main>` needs no label).

### 2. **[critical] A11y craters to 75–79 whenever a controls panel is open — the editing UI was never audited** — disposition: SHIP (gate scope) + outward asks (fixes)
`after-prod/_summary.json`: home/spring (panel-closed start screen) = A11y **98**; amiga/easing = **78–79**; square = **75**. The delta is entirely the open controls panel, whose fails are `button-name`, `label`, `aria-input-field-name` (+ `color-contrast` on square). The dev `_summary.json` shows 92–98 because it audited the start screen with no animation selected — so **W5's "A11y closed" gate measured a state the user almost never sits in.** This is the headline finding: the gate's *scope* was wrong, not just a missing fix.
**Gestalt fix:** The CI a11y gate (finding 11) must drive each scene into its *open-panel* editing state (select an animation, open Controls/Keyframes/Timeline tabs) before scoring — audit the product as used, not the splash.

### 3. **[critical] glass-ui `LabeledField` renders a `<label>` with no control association — single root cause of `label` + `button-name` + `aria-input-field-name`** — disposition: BOOK → outward ask (glass-ui-owned, inv-16)
`glass-ui/src/components/custom/labeled-field/LabeledField.vue:2-17` emits a bare `<label>` (no `for`), and the four wrappers (`LabeledInput.vue:9`, `LabeledSelect.vue:8`, `LabeledSlider.vue:8`, `LabeledSwitch.vue:9`) slot a control with **no matching `id` and no `aria-labelledby`**. Result in `after-prod/square-mobile.json`: `label` (4 `input.input-pill`), `button-name` (4 `button.glass-wash` combobox triggers + 1 `role="switch"`), `aria-input-field-name` (1 `slider-thumb` `role="slider"`). The `Slider.vue:163` *does* forward `$attrs['aria-label']` to the thumb, and `Switch.vue` could carry `aria-labelledby` — but `LabeledField` passes neither down. Every keyframes demo (and every other glass-ui consumer) inherits the defect.
**Gestalt fix (in glass-ui, not patched in demo):** `LabeledField` mints `const labelId = useId()`, renders `<label :id="labelId" :for="controlId">`, and exposes both `{ labelId, controlId }` as slot-props. Labelable controls (`<input>`) bind `:id="controlId"`; ARIA-widget controls (reka-ui combobox button, `role="slider"`, `role="switch"`) bind `:aria-labelledby="labelId"`. One parent-SFC change closes `label`, `button-name`, and `aria-input-field-name` across the constellation. File as a new outward ask alongside the two in `docs/tranches/B/asks/glass-ui-adoption-asks.md` (currently only dock-double-click + VAL-9).

### 4. **[high] `color-contrast` on `.square-box` text — demo-owned** — disposition: SHIP (demo-owned)
`demo/app/scenes/SquareScene.vue:51` sets `background-color: aquamarine` (#7FFFD4) on a box whose `"heyyyy"` text inherits the theme foreground with **no explicit `color`** (line 39-53 has no `color`). On dark theme the inherited light foreground on aquamarine fails AA; lighthouse flags `div.square-box` in `after-prod/square-mobile.json` (`color-contrast` score 0). This is the *only* `color-contrast` fail in the suite (square desktop+mobile).
**Gestalt fix:** This box is a *swatch on a known background* — its on-color must be derived from that background, not inherited from the theme. Set an explicit high-contrast on-color: `color: var(--gray-950)` (or a glass-ui `--on-accent`-style token) so the text is dark-on-aquamarine regardless of theme. Aquamarine itself can stay (it's the demo's identity), but the text color must be background-relative, not theme-relative.

### 5. **[high] Scene-icon `<img>` in `DockSelectTrigger` flagged `image-alt`, despite TopDock passing `:alt`** — disposition: SHIP (demo-owned) + verify glass-ui passthrough
`after-prod/square-mobile.json` `image-alt` flags `button.dock-select-trigger > img.w-5` with no alt. `TopDock.vue:173` *does* set `:alt="\`${currentSceneId} scene\`"` on the trigger img — so the flagged node is a path where alt is dropped: most likely the **collapsed-pill img (`TopDock.vue:212`)** or the AnimationMenuBar select-icon, where the img renders without alt. Plus two demo imgs are genuinely alt-less: `KeyframeTimeline.vue:107` (keyframe preview) and `AssetViewport.vue:59` (asset image).
**Gestalt fix:** Audit every `<img>` for an `alt`. Decorative dock/scene icons (the label already names the scene) → `alt=""` (explicitly empty = decorative, satisfies the rule without redundant SR noise). Content imgs (`AssetViewport` user image) → `:alt="asset.text ?? 'asset'"`. Keyframe preview (`KeyframeTimeline:107`) → `:alt="\`keyframe at ${Math.round(kf.percent)}%\`"`. Confirm glass-ui's `DockSelectTrigger` forwards `alt` from the slotted img (if it wraps, that's a glass-ui passthrough bug → outward).

### 6. **[high] MatrixEditor raw `<Slider>` and EditableLabel rename `<input>` have no accessible name** — disposition: SHIP (demo-owned)
`demo/@/components/custom/matrix-editor/MatrixEditor.vue:67` renders a bare `<Slider>` with no `aria-label` (the cube/matrix tab) — the thumb forwards `$attrs['aria-label']` (`Slider.vue:163`) but none is passed → another `aria-input-field-name` source on the cube scene's matrix panel. `demo/@/components/custom/EditableLabel.vue:7` renders a rename `<input>` with no `aria-label`/label → another `label` fail when active.
**Gestalt fix:** MatrixEditor: `:aria-label="\`matrix cell ${matrixCellMeta[selectedCell].axis}\`"` on the `<Slider>` (the value is dynamic per selected cell — name it from `matrixCellMeta`). EditableLabel: `:aria-label="\`rename ${modelValue}\`"` on the input. Both are semantic names from existing data, not generic strings.

### 7. **[medium] Dock icon-button touch targets are 40px on mobile — below the 44px WCAG 2.5.5 / Apple HIG minimum** — disposition: BOOK → outward ask (glass-ui token default)
`glass-ui/src/styles/dock.css:716` sizes `.dock-icon-button` to `var(--dock-control-size, var(--size-icon-btn))` = 2.5rem (40px); the 44px (2.75rem) value only appears under `--dock-density-spacious` (dock.css:120) and the 44px tab-min-height under audacious (dock.css:144). The bottom dock on mobile (`home-mobile.png`, `square-mobile.png` — reset/trash/play row) and the compact easing-edit/back buttons (`AnimationControlsControls.vue:72,126`) thus ship sub-44px touch targets. Lighthouse doesn't gate tap-target by default but it's a real WCAG 2.1 AA (2.5.5) / AAA touch fail visible in the mobile screenshots.
**Gestalt fix (glass-ui-owned):** glass-ui should default `--dock-control-size` to 44px under a coarse-pointer media context (`@media (pointer: coarse)` → spacious density), so every dock on touch surfaces meets the minimum without per-consumer overrides. File as outward ask; keyframes' enabler is none (pure glass-ui token-default change).

### 8. **[medium] Hero `<h2>` hint "or drag M. cubert" relies on emoji + inline `<List>` icon mid-sentence at 50% opacity — low contrast, fragile semantics** — disposition: SHIP (demo-owned)
`EditorStartScreen.vue:24` injects a `<List>` lucide icon *inside* an `<h2>` sentence ("from the list `<icon>` above.") and line 28 sets the hint `<h2>` to `opacity-50`. The icon mid-prose has no accessible text (it's a meaningful "list" reference rendered as a decorative SVG), and 50% opacity on the hint likely fails contrast. Visible in `home-mobile.png` (the muted "or drag M. cubert 🥯" line and the inline glyph that reads as noise). The design-findings.txt already rated this medium (lines 78-81).
**Gestalt fix:** The inline `<List>` should be `aria-hidden="true"` (it's decorative reinforcement of the word "list" already in the sentence) OR carry an `aria-label`. Replace `opacity-50` with a token-driven `text-muted-foreground` step that meets AA (opacity multiplies into the background and breaks contrast math; a contrast-checked token does not). The "M. cubert 🥯" emoji should not be the sole carrier of meaning — it already pairs with text, so wrap the emoji `aria-hidden` to silence the SR babble.

### 9. **[medium] Focus order / focus-visible: dock controls keep glass-ui rings, but teleported PlaybackRibbon + advanced-pane `role="button"` divs need a focus-order audit** — disposition: RECORD (verify in C)
glass-ui ships `.focus-ring` + `--focus-ring-shadow` (`tokens.css:994`, `utilities.css:140`) and `.dock-icon-button:focus-visible` (dock.css:760), so the *primitive* focus-visible story is sound (not a gap). The risk is **focus order**: `AnimationControlsControls.vue:91-98` makes the "advanced" navigation a `<div role="button" tabindex="0">` (keyboard-handled, OK) and `PlaybackRibbon` / `AnimationControls` are `Teleport`-ed (`AnimationControlsControls.vue:154`, `KeyframeTimeline` teleport) — teleported DOM moves the focus order away from its visual position, which can produce a confusing tab sequence between the panel and the ribbon.
**Gestalt fix:** C should run a keyboard-only pass (Tab through cube/square with panel open) and confirm the teleport targets (`#controls-ribbon-target`, timeline expansion) land in a sensible visual order; if not, co-locate the teleport target in DOM order or add a roving-tabindex. No code change asserted yet — RECORD for C's manual verification, since teleport focus order can't be caught by axe/lighthouse.

### 10. **[low] `title`-only naming on the 4 titled DockIconButtons is technically sufficient but the `IconTooltip` wrapper is the semantic home** — disposition: RECORD
`AnimationMenuBar.vue:75,84,113` and `AnimationControlsControls.vue:72,128` use `<DockIconButton title="…">`; glass-ui's `DockIconButton.vue:52` passes `title` through fallthrough attrs to the `<button>` host. axe/lighthouse `button-name` *accepts* `title` as a name source, so these don't fail — but `title` is invisible to touch and unreliable for SR. They're already wrapped in `<IconTooltip text="…">`, so the canonical name already exists adjacent. The brief's "11 DockIconButton without title/aria-label" did not reproduce — current grep shows only titled or compact-with-title instances; the *real* button-name fails (finding 3) come from glass-ui's `glass-wash` select/switch buttons, not `DockIconButton`.
**Gestalt fix:** Have glass-ui's `IconTooltip` thread its `text` onto the wrapped control's `aria-label` (so the tooltip IS the accessible name, single source of truth) — minor outward refinement, not a blocker. RECORD; correct the inventory in C's plan (the "11 DockIconButton" figure is stale).

### 11. **[critical] CI a11y-score gate (W5's deferred hard gate) — Lighthouse A11y = 100 on the OPEN-PANEL state** — disposition: SHIP (new CI gate)
W5's §Hard gate text demanded "lighthouse A11y = 100" but FINAL.md only shipped `<main>`/alt assertions and self-certified against the start screen; no scoring gate exists in CI, and the real product state scores 75–79 (finding 2). The B audit harness already produces per-scene `after-prod/*.json` — the machinery exists; only the gate + correct state is missing.
**Gestalt fix:** Add a CI job that (a) builds the prod demo, (b) for each scene navigates AND drives it into its open-panel editing state (select first animation, open each control tab — the exact transitions `App.vue:364-379` already perform on mount), (c) runs Lighthouse a11y, (d) **fails the build if any scene's accessibility < 100**. Wire it as a hard gate beside B.W6's demo-smoke/occlusion gates. This gate is only honest once findings 1 and 3 land (the `display:contents` main + the glass-ui `LabeledField` association); sequence C so the glass-ui ask (finding 3) ships first, then flip the gate to 100. Until glass-ui ships, the gate can assert the *demo-owned* closes (findings 1, 4, 5, 6, 8) at the panel-open state and hold the glass-ui-blocked audits (`button-name`/`label`/`aria-input-field-name`) as a tracked allowance that the gate removes on glass-ui adoption.
