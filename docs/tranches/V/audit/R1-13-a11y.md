# Lane R1-13 — Accessibility Census (prefix AY-)

Date: 2026-07-16. Scope: source-level a11y census of `demo/` (aria correctness, focus
management, keyboard operability of custom controls, reduced-motion honoring, form
labels, Monaco flags). Live pass not attempted (source-level census sufficient; dev
server not started to avoid contending with active sibling agents).

## Verdict

The demo is, on the whole, a mature a11y surface: custom `role="slider"` controls
(SpringTarget, SquareScene, SequenceScrubber, SequenceTarget, TimelineTrack markers,
SpringHeatmap `role="application"`) each carry real `@keydown` arrow/Home/End handlers
and `aria-valuemin/max/now` — none are pointer-only. Dialogs/popovers ride glass-ui
`Dialog`/`Popover`/`Drawer` primitives (native focus trap + restore). The keyframes
toolbar has a genuine roving-tabindex composable (`useToolbarKeyboard`), and the
inactive Monaco pane is taken out of the tab order with `inert` (not the aria-hidden-focus
trap). Live regions (`role="status" aria-live="polite"` in CopyButton, `aria-busy` in
the skeleton) are correct. `role="textbox" aria-multiline="true"` on the KeyframeCard
contenteditable `<pre>` is correctly paired.

Four defects survive. The two P2s are concrete and demonstrable: (1) the Amiga scene —
the most motion-heavy scene — honors `prefers-reduced-motion` NOWHERE (no
`respectReducedMotion`, no CSS PRM guard) while every other scene does; (2) Monaco is
explicitly configured `accessibilitySupport: "off"`, which disables its screen-reader
accommodations on the primary CSS-editing surface. Both are kf-demo-owned (not glass-root).

## AY-1 — Amiga scene ignores `prefers-reduced-motion` entirely — P2

Family: `reduced-motion-gap`. Owner: kf-demo.

The Amiga scene runs three `iterationCount: Infinity` `CSSKeyframesAnimation`s — a linear
sphere spin, wall-to-wall X bounce, and a gravity-flavoured Y slam — plus a Three.js
sphere spin, with NO reduced-motion honoring on any surface:

- `demo/scenes/amiga/useAmigaDemo.ts:93,110,127` — the three infinite
  `CSSKeyframesAnimation({ duration, iterationCount: Infinity, timingFunction })`
  constructors pass NO `respectReducedMotion`. Per
  `src/animation/internal/reduced-motion.ts` the policy defaults to `false`/`undefined`
  = "do not honor reduced motion (the conservative default; the animation runs at full
  amplitude regardless of the OS query)". So under an active query these keep bouncing
  wall-to-wall and spinning at full amplitude.
- `grep -rn 'respectReducedMotion' demo/scenes/amiga/` → no matches.
- `grep -rn 'reduced-motion|prefersReduced|matchMedia' demo/scenes/amiga/` (across
  `useAmigaThree.ts`, `AmigaScene.vue`, `useSphereSpin.ts`, `.ts`) → no matches; and there
  is no `@media (prefers-reduced-motion: reduce)` block anywhere in `demo/scenes/amiga/`.
- Contrast: every OTHER scene honors it — `cube/useCubeDemo.ts:164` and
  `sequence/useSequenceInstrument.ts:31` snap via `matchMedia`,
  `easing/EasingTarget.vue:234` via `useMediaQuery`, and spring/square/square-instrument
  carry `@media (prefers-reduced-motion: reduce)` CSS. Amiga is the lone outlier.

Note: `AmigaScene.vue:105,116` mentions a `SpringProgress` re-seat that "PRM snaps" on
STOP — that only covers the settle-home spring, not the continuous bounce/spin that is the
scene's actual motion. WCAG 2.3.3 concern (vestibular). The library already ships the
mechanism; the demo simply never wires it here.

Disposition: BUILD (small) — pass `respectReducedMotion: true` (or a policy scale) to the
three Amiga `CSSKeyframesAnimation`s, and gate the Three sphere spin on a `matchMedia`
check mirroring cube/sequence. One wave.

## AY-2 — Monaco CSS editor sets `accessibilitySupport: "off"` — P2

Family: `monaco-a11y-disabled`. Owner: kf-demo.

`demo/components/instrument/keyframes/CSSCodeEditor.vue:144` — the Monaco editor is
created with `accessibilitySupport: "off"`. Monaco's contract: `"off"` = "the editor will
never be optimized for usage with a Screen Reader"; the default `"auto"` detects an AT and
switches to the screen-reader-optimized textarea + ARIA plumbing. Hard-coding `"off"`
strips those accommodations from the demo's primary code-authoring surface (the keyframes
CSS editor is a core interactive control, mounted via `keyframes/index.ts` /
`ChannelControls.vue`). Screen-reader users editing CSS get the degraded, non-optimized
path with no way to opt back in.

Disposition: BUILD (trivial) — change to `"auto"` (or expose it as a prop defaulting to
`"auto"`). Verify no perf regression was the reason for the override; if it was, document
the tradeoff instead of silently disabling AT support. Fold into the same wave as AY-3/4.

## AY-3 — MatrixEditor value cells are unlabeled inputs — P2

Family: `form-label`. Owner: kf-demo.

`demo/scenes/cube/matrix-editor/MatrixEditor.vue:16-40` — each of the 16 editable matrix
cells is a glass-ui `<Input>` with NO `aria-label`, `id`+`<label for>`, or
`aria-labelledby`. The only visible label is a SIBLING decorative `<div>`
(`MatrixEditor.vue:41-57`) carrying the axis text (e.g. "X", "translateX") styled at
`opacity-20` — it is neither `aria-hidden` nor associated with the input. Result: a screen
reader announces 16 identical unnamed text fields (the axis `<div>`s read as loose static
text, unlinked). The `<Slider>` at line 61 that drives the selected cell is a glass
`Slider` (labeled internally), but the per-cell inputs — the primary edit affordance — are
nameless.

Disposition: BUILD (small) — bind `:aria-label="matrixCellMeta[i].axis + ' ' + transform"`
on each `<Input>` (the meta already exists at line 47), and add `aria-hidden="true"` to the
decorative axis `<div>`.

## AY-4 — TimelineCaret edit input unlabeled + click-to-edit is pointer-only — P3

Family: `form-label` / `keyboard-operability`. Owner: kf-demo.

`demo/components/instrument/timeline/TimelineCaret.vue:14-27` — the `<input type="number">`
that edits a keyframe's percent has no `aria-label`/label (min/max present, name absent).
Additionally the non-editing display (`:14` `<div @click.stop="startEdit">`) is a
click-only trigger with no `tabindex`/`@keydown` — a keyboard/AT user cannot reach the
inline percent edit through the caret. Severity held at P3 because keyframe percent IS
independently keyboard-editable via the `role="slider"` markers in
`TimelineTrack.vue:74-82` (arrow/Home/End), so the caret is a redundant pointer
convenience rather than the sole path.

Disposition: FOLD into the AY-2/AY-3 label wave — add `aria-label="Edit keyframe percent"`
to the input; optionally make the display a real `<button>` for parity.

## AY-5 — `aria-errormessage` without `aria-invalid` on z-index input — P3

Family: `aria-inert-attr`. Owner: kf-demo (borderline glass-contract).

`demo/components/instrument/transport/channel-controls/LayerConfigPanel.vue:41` — the
z-index `<Input>` binds `:aria-errormessage="errorId"` but never sets `aria-invalid`. Per
ARIA, `aria-errormessage` is only surfaced to AT while the element is `aria-invalid="true"`;
with no invalid state (and no error node rendered) the reference is inert. Harmless but
dead — cargo-culted from the auto-wiring wrappers referenced in the adjacent comment.

Disposition: RETIRE the attribute, or wire a real `:aria-invalid` from validation state.

## Negatives (checked, found sound)

- Custom sliders keyboard-operable: SpringTarget (`:65-72`, `onKeydown :254`), SquareScene
  (`useSquareKeyboard`, `:300`), SequenceScrubber (`:29`), SequenceTarget rows (`:106`),
  TimelineTrack markers (`:82`), SpringHeatmap `role="application"` (`:35`, `onKeydown
  :235`). None pointer-only. Each carries `aria-valuemin/max` and a live `:aria-valuenow`
  (SquareScene adds per-axis `aria-valuetext`).
- Focus trap/restore: dialogs (KeyboardShortcutsModal, KeyframesAddDialog) and popovers
  (SharePopover) use glass-ui `Dialog`/`Popover` (reka-ui) primitives — native trap +
  focus restoration; ControlsPaneWrapper Drawer noted as focus-trap + page-aria-hidden.
- Roving tabindex: `useToolbarKeyboard.ts` implements a real Arrow/Home/End roving set over
  live button descendants (`:63,69,76`); the decorative wand is `aria-hidden` and excluded.
- `inert` (not aria-hidden) taken on the inactive Monaco pane — `ChannelControls.vue:136`
  `:inert="!keyframesActive"` — correctly avoids the aria-hidden-focus defect.
- `role="textbox" aria-multiline="true"` correctly paired on the KeyframeCard
  contenteditable `<pre>` (`KeyframeCard.vue:47-49`) with an `:aria-label`.
- Live regions: `CopyButton.vue:15` (`role="status" aria-live="polite"` + `sr-only`),
  `App.skeleton.vue:30-32` (`role="status" aria-busy`). Decorative twins correctly
  `aria-hidden` (AnimationVisualizer, HeroAurora, AnimatedText visual layer with an
  `sr-only` phrase mirror, SquareInstrument telemetry, SequenceAxis/Playhead).
- Every `aria-label` grepped (107 occurrences) names a real control; no `aria-describedby`
  dangling-id defects found (the only id-relationship uses are LabeledField's slot
  `controlId`/`errorId`, which are provider-generated).
- No non-Amiga reduced-motion gaps: 5/6 scenes honor PRM (CSS and/or JS).

## Coverage gaps

  concern (read-only sibling; not opened). If a glass primitive is internally broken, these
  demo-level positives would be undermined — flag for the glass batch letter.
- No live AT/axe pass (dev server not started). Contrast ratios, real focus-order, and
  runtime `aria-live` announcements were not measured — source-level only.
- Monaco's runtime ARIA/textarea behavior under `accessibilitySupport:"off"` asserted from
  the documented contract, not observed live.
- `EasingTarget` family-filter buttons and TransportDock `Select` keyboard behavior assumed
  from glass-ui/native semantics; not exercised live.
