# B.W2 — Engine debt transposed (gestalt)

The headline engine wave. A's three `internal/` consolidations
(`reduced-motion.ts`, `easing-resolvable.ts`, `scheduler.ts`) deleted real
duplication but unified only halfway: reduced-motion is one detector with seven
hand-written snap bodies, the managed-rAF loop is copy-pasted three ways, and the
`AnimationGroup` reset/fill/completion tangle forced `_playReducedMotion` to be a
fork of `reset()`. W2 finishes the unification with architectural transpositions —
not patches — per the no-workaround/no-legacy/no-alias mandate. Grounds:
`audit/architecture-gestalt.md` (B1/H1/H2/H3/M1-M4 + the top-3) and the
boundary/fail-explicit findings in `audit/plan-findings.txt`.

## § Goal

The engine's debt is transposed so the contracts the half-finished consolidations
implied actually exist — one rest-position contract, one managed-rAF driver, one
reduced-motion gate, one typed easing value, one explicit option-validation seam —
and the boundary gate proves the whole light surface, not one entry. Every change
deletes more than it adds; no new workaround, legacy path, or alias is introduced.

## § Scope

### S1 — The rest-position / fill contract (retires the cube-cutoff workaround) — B1
**What:** introduce an explicit "where the playhead rests after a play completes"
contract that dissolves the three entangled behaviors in `group.ts`
(`:421` draw-resets-on-completion, `:537-556` `reset()` + TODO(HIGH) `:540`,
`:459-489` `_playReducedMotion`'s forked settle). Separate the three orthogonal
concepts currently fused:
- `settle()` — pure state teardown (flags, handle, time), **never paints** (this is
  what child `Animation.reset()` at `engine.ts:841` already is).
- `restPosition: 'initial' | 'final' | 'hold'` — derived ONCE from `fillMode`
  (forwards→final, backwards/none→initial). Completion paints the rest frame per
  this contract, not unconditionally to frame 0.
- Reduced-motion becomes "rest = final, paint it, `settle()`" — the **same** path
  `fillMode: forwards` completion takes, not a bespoke fork.

**Why:** the cube-cutoff repaint (`interpFrames(0,true)` in `reset()`) is a *symptom*
of the missing contract; the normal-completion-resets-to-initial quirk and
`_playReducedMotion`'s 9-line "why I can't call reset()" comment are the other two
symptoms. One contract retires all three — the TODO(HIGH) deletes, the fork deletes,
the quirk resolves. This is the canonical workaround-spawns-workaround disease cured
at the root.

### S2 — One managed-rAF driver + one reduced-motion gate — H1 + H2 + L1
**What:** generalize `RAFPlayback` into the single managed loop over a `Tickable`
interface (`tickDt(dt): void; settled: boolean; sample(): T`). `SmoothProgress`,
`SpringProgress`, and `NumericAnimation` become pure *steppers* that delegate all
loop ownership; the two `_startLoop`/`_stopLoop` copies (`smooth.ts:200-223`,
`spring.ts:385-409`) and the per-class `_rafId`/`_lastFrameT`/`_onFrame` triples are
deleted, along with `AnimationGroup`'s hand-rolled fourth rAF loop. Then define one
`withReducedMotion(detector, snap, run)` gate (`if (respect && detector()) return
snap(); return run()`) that every play path calls, with a `snapSettled(target, emit)`
helper — collapsing the seven hand-written snap bodies (`playback.ts:68-71`,
`engine.ts:762-772`, `group.ts:459-489`, `smooth.ts:87-92`+`:178-183`,
`spring.ts:170-180`+`:365-371`) into five one-line `snap` closures.

**Why:** `RAFPlayback` was introduced as "the shared loop so interpolators don't each
reimplement it" — but smooth/spring don't use it. The abstraction exists *and* is
duplicated. The directive's exact question ("could the heavy/light reduced-motion be
ONE contract?") is yes. Net deletion across five files.

### S3 — Typed easing value + explicit option validation — M1 + M3 + H3
**What:** three coupled transpositions.
- Replace the two Symbol-on-a-closure side channels (`css-easing.ts` `cssEasing`,
  `renderer.ts:18` `DEFAULT_RENDERER`) with a visible typed value:
  `interface Easing { fn: TimingFunction; css?: string }` (or branded `EasingSpec`).
  `springTimingFunction` returns `{ fn, css: linear(...) }`; `waapi.ts` reads `.css`
  through the type system. The "tag survives wrapping" invariant becomes a checked
  field, not a Symbol that silently evaporates.
- Replace the async-resolver-on-a-sync-API (`EasingResolvable` + the strippable
  dev-warn) with an explicit `await resolveEasing(name): Promise<Easing>` factory:
  the light engines accept only callable `TimingFunction`s (truly value.js-free,
  sync, no resolver), and a name is resolved once, up front. No pending state, no
  identity fallback, no warn coupled to `esbuild.drop`, no `EasingResolvable` class.
- One `parseOption(raw, validator, name)` seam + a `strict` policy on
  `AnimationOptions`: malformed input throws a typed `AnimationOptionError` with the
  offending value + option name; defaulting happens only for genuine `undefined`.

**Why:** the codebase already chose throw-on-bad-input for the layer API
("silent no-ops were hiding consumer bugs", `group.ts:590`) but the option setters
swallow malformed input (`setIterationCount("abc")` no-ops, `setDuration(-5)` keeps
the old value, `setTimingFunction("bogus")`→easeInOutCubic) — the CRITICAL TODO at
`engine.ts:412` + four HIGH siblings. This is the **fail-explicit invariant A
declared but did not honor** (the silent-permanent-identity easing degradation). One
decision retires the nine setter TODOs and honors the invariant.

### S4 — Widen `proof:boundary` to every light entry point
**What:** `scripts/proof-boundary.mjs` builds only the `SpringProgress` entry — five
of seven light modules (`SmoothProgress`, `NumericAnimation`, `ElementMorph`, the
`Timeline` family) are unproven. Widen the gate to bundle EACH light entry (or a
combined light-barrel entry) and assert zero static value.js / `engine.ts` edge for
all. **Why:** a static value.js edge in a light module `SpringProgress` does not
transitively reach passes inv α today — the gate's prose ("the boundary is gated")
exceeds its coverage.

### S5 — Residual hardening (the LOW/INFO cluster)
- Eager-resolve/`resolveEasing` `import("./engine")` gets a `.catch` — a chunk-load
  failure surfaces, not an unhandled rejection (plan-audit finding).
- WAAPI multi-stop spring (M2): bake the spring into densely-sampled keyframe stops
  (reuse the 64-pt sampler) + emit `easing:"linear"` so per-segment linear IS the
  true curve — or reject `frames.length>2` for tagged easings in `isWAAPIEligible`.
- `handleId: number | any` (`engine.ts:89`, `group.ts:72`) → the correct
  `ReturnType<typeof requestAnimationFrame> | null` already in `RAFPlayback`.
- `AnimationGroup.play()` gains the `_playingPromise` reentrancy guard `Animation`
  has (L5) — double `play()` no longer leaks an rAF loop.
- `CSSKeyframesAnimation.from*` triple-dup → one `resolveTransform()` (L2);
  `isNumericCarrier` duck-typing → `instanceof ValueUnit` / typed blend strategy (L4);
  `scheduler.ts` strategy cached once (L3).
- ScrollTimeline native (`timeline.ts:196`, chronic): feature-detect native
  `animation-timeline: scroll()/view()` beside the JS fallback (Baseline-Newly).

## § Design decisions

- **Transposition, not patch.** Each S-item is the gestalt fix the architecture audit
  named, not the localized workaround. The rest-position contract is the linchpin —
  it is what makes reduced-motion "just fillMode=forwards completion" rather than a
  fifth code path.
- **No-alias on the easing change.** `EasingResolvable` is DELETED, not kept beside the
  new `resolveEasing` factory; the string-name path moves from a synchronous lie with
  a fallback to an explicit async construction step. This is a behavior change at the
  construction boundary, cleanly — no compatibility shim.
- **strict default.** `strict` defaults to throwing on malformed input (matching the
  layer API); genuine omission (`undefined`) still defaults. No flag is needed to get
  the correct posture — the flag, if any, opts *out* for lenient hosts.
