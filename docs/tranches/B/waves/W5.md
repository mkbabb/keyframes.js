# B.W5 — Design system (φ-ladder + serif + a11y/SEO)

glass-ui 3.1.1 — already a dependency — ships a complete golden-ratio type system
(`--type-*` rungs √φ→φ^(11/2), `text-display-*` / `text-heading` / `text-title` /
`text-subheading` / `text-prose` / `text-body`), yet the demo uses NONE of it: every
surface is sized with raw Tailwind rungs that sit off the φ-ladder, on a forked
serif. W5 adopts the canonical system, resolves the dual-serif split, migrates the
residual ad-hoc CSS, and closes the lighthouse a11y/SEO regressions. Grounds:
`audit/design-findings.txt` (typography + glass-ui-idiom dimensions) and
`audit/lighthouse/_summary.json` (A11y 92-98, SEO 75-82).

## § Goal

The demo's type and surface vocabulary is glass-ui-idiomatic: one display serif on
the φ-ladder, raw Tailwind display rungs retired, ad-hoc CSS migrated to glass-ui
tokens, and the a11y/SEO regressions closed. glass-ui-owned defects route outward as
adoption asks, never patched in the demo.

## § Scope

### S1 — Adopt the glass-ui φ-ladder type utilities
**What:** replace the demo-wide raw Tailwind rungs (`text-2xl`×?, `text-5xl`,
`text-6xl`, `text-8xl`, body `text-sm`×30/`text-base`×18/`text-lg`/`text-xl`) with
glass-ui's semantic utilities: hero (`EditorStartScreen.vue:6`, currently
`text-6xl lg:text-8xl` = 60/96px, landing BETWEEN φ-rungs) → `.text-display-mega` (or
`.text-hero`/`.text-display-hero` for the poster register), headings →
`.text-heading`/`.text-title`/`.text-subheading`, body → `.text-body`/`.text-prose`,
admin/labels → `.text-small`/`.text-caption`/`.text-admin-label`. **Why:** the hero
sits off the φ-ladder and the entire demo bypasses the canonical scale — a glass-ui
idiom breach the audit rated high. The utilities carry the golden-ratio clamp,
optical sizing, and display variation settings the raw rungs lack.

### S2 — Resolve the dual display-serif to one canonical face
**What:** the demo overrides glass-ui's `--font-serif` to "Instrument Serif"
(`demo/@/styles/style.css:7`) and applies a `.instrument-serif` alias 49 times, while
glass-ui's display face (`--font-display` = Fraunces) only ever surfaces in the asset
playground — so two serifs diverge by surface rather than pair deliberately, and a
third family (Fira Code mono) sits in the dock "@mbabb" badge. Decide the brand
intent explicitly: formalize Instrument Serif as the canonical display face by
setting `--font-display: "Instrument Serif"` (and aligning `--font-serif`), so the
hero, dropdown, dock labels, and the playground all speak ONE display serif. Drop the
per-component `.instrument-serif` alias in favor of the semantic utilities (S1).
**Why:** the dual-serif split is unintentional and incoherent; the audit's resolution
is one display serif, formalized in the token system, not a per-surface override.

### S3 — Migrate residual ad-hoc CSS to glass-ui tokens
**What:** the surface/blur/shadow/motion layer is already idiomatic (zero hand-rolled
`backdrop-filter`/`blur()`, glass surfaces via `.glass-card`/`.glass-wash`, docks from
glass-ui primitives, motion via `--duration-*`/`--ease-*`/`--spring-*`). The residual
breaches: `CSSCodeEditor.vue` hand-rolls a cartoon shadow
(`shadow-[4px_4px_0px_0px_rgba(0,0,0,0.6)]` + `border-gray-700`) → `.cartoon-surface`
/ `--shadow-cartoon-md`; the `index.html` loading splash hardcodes off-token colors
(`#1a1a1a`/`#fff`/`#0a0a0a`/`#e5e5e5`) — resolved by its removal in B.W4. **Why:** the
last ad-hoc surfaces should consume the canonical tokens.

### S4 — Close the a11y regressions
**What:** lighthouse flags `landmark-one-main` (no `<main>` landmark) and `image-alt`
(images missing alt) across pages — A11y 92-98. Add a single `<main>` landmark to the
app shell and alt text to the decorative/content images (the `ppmycota` logos, the
cube-icon). **Why:** real, dev-independent a11y failures; cheap to close.

### S5 — Close the SEO regressions
**What:** SEO 75-82 across pages. Investigate + fix (meta description, document title
per scene, the hash-routed SPA's crawlability, `robots`/canonical). **Why:** a
published demo should not score sub-85 on SEO basics.

### S6 — Outward asks (glass-ui-owned, never patched in the demo)
**What:** two glass-ui adoption asks: (a) the dock double-click bug — masked in the
demo by `always-expanded` on mobile, but the bug lives in glass-ui's
`useTouchGate`/`GlassDock` and is glass-ui-owned; (b) VAL-9 — glass-ui regenerates its
committed-static `--spring-*` `linear()` tokens from keyframes' `springLinearStops()`
mint so they cannot drift from the solver. **Why:** the standing rule — glass-ui
changes go in glass-ui, never patched in the demo.

## § Hard gate

`grep` confirms zero raw display rungs on the hero (φ-ladder utilities only); one
display serif resolved in the token system (no `.instrument-serif` alias residue);
the cartoon-shadow ad-hoc CSS migrated; lighthouse A11y = 100 (`landmark-one-main` +
`image-alt` resolved) and SEO ≥ 90 on the fixed prod build; the two outward asks filed
in glass-ui.

## § Design decisions

- **Adopt, don't re-author.** glass-ui already ships the φ-ladder; W5 consumes it. No
  new type scale is invented in the demo.
- **One display serif, formalized.** The resolution is to make Instrument Serif the
  canonical `--font-display` (the demo's identity face) rather than leaving it a
  `--font-serif` override that collides with Fraunces — a token decision, not a
  per-surface patch. (If the constellation prefers Fraunces as the shared display
  face, the alternative is to drop the Instrument override entirely; the wave records
  Instrument-as-identity as the recommended resolution.)
- **glass-ui defects route outward.** Per the standing rule + project memory, the dock
  double-click is fixed in the glass-ui repo, never in the demo; W5 files the ask, it
  does not patch.
