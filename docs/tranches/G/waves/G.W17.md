## §Goal

Make the `add` and `weighted` blend modes RUN — the value-level twin to `proof:zero-alloc` (which proved the buffer doesn't allocate; this proves it holds the RIGHT number). The fix is a CONTAINED element-wise transposition of the existing (dead) blend leaves: loop the array elements `min(existing.length, incoming.length)`, blend each pair in place when both are numeric, else replace that index. The in-place mutation (mutate `existing[i].value`) is preserved — zero-alloc intact, the `_grouped` fast-properties discipline untouched. KISS · DRY · zero new machinery. The multi-element color/multi-arg leaf is covered FOR FREE by the loop (GL-2) — written as a loop FROM THE START, never a length-1 shortcut (Mandate: NO special cases).

## §Scope

When an index is non-numeric (a string/computed leaf component) replace that index (`existing[i] = incoming[i]`). When the whole leaf is non-array (defensive) keep the existing `else` replace. **WHY:** the leaf is a `ValueUnit[]`; the guard must match its real shape, and the element loop covers the multi-component leaf (a color `ValueUnit[]` of length N, or two component-arrays of differing length) WITHOUT a length-1 special case (`a-group-layering.md:119-131,144-166`). ## §Design decisions (trade-offs RESOLVED)

- **The leaf shape, not the guard semantics, is the bug — RESOLVED.** The audit names a tempting wrong fix: tighten `isNumericUnit` to ALSO accept a one-element array. That is a length-1 special case the Mandate forbids and GL-2 falsifies (a multi-element color leaf would still degrade). The gestalt fix guards on the ARRAY and loops the elements `min(existing.length, incoming.length)`, reusing `isNumericUnit` PER ELEMENT — the multi-component leaf is covered for free, written as a loop from the start (`a-group-layering.md:119-131,160-166`).
- **In-place mutation preserved — zero-alloc intact — RESOLVED.** The blend mutates `existing[i].value` in place exactly as the dead leaves did (`group.ts:309-310,335-339`), one indirection inward (array element, not the array). No fresh object per blend, the `_grouped` fast-properties discipline (F.W4 S2) untouched, `proof:zero-alloc` stays green. The fix is a transposition of the existing leaves, NOT new machinery (`a-group-layering.md:124-131`).
- **`add` does NOT clamp — RESOLVED (GL-6), value.js-HANDOFF RECORD-only.** Numeric add is un-clamped (CSS `animation-composition: add` does not clamp at composition; clamping is at use) — the CSS-correct contract, encoded in `proof:blend` (c). A per-property clamp would need a range-aware `ValueUnit` (value.js carries no per-property range metadata) — RECORD as the ONLY path to per-property clamping should it ever be wanted; recommend NOT clamping, and do NOT special-case opacity in `group.ts` (`a-group-layering.md:273-283`).
- **The `add` semantic on a color/transform-list leaf is FB-1's question, not G.W17's — RESOLVED.** G.W17 makes the leaf blend MECHANICALLY correct (operate on the array). The SEMANTIC question — "what does `add` mean for a color or a transform-list" (concat-vs-sum, NEW-39) — is the FB-1 BOOK (`a-group-layering.md:168-173,226-232`). G.W17 ships the correctness floor (the arm runs, the value is right per the numeric-add contract); FB-1 decides the higher-level composition semantic on top of a working leaf. Note the component decomposition (`frame-compiler.ts:364` splits multi-arg transforms into per-component keys — `a-group-layering.md:152-158`) already gives per-component additivity, the useful half.
- **Independent of the spine, sequenced before FB-1 — RESOLVED.** This is a kf-local source correctness fix with ZERO dependency on the re-pin (`G.W2`) — it CAN land in parallel. But it MUST land BEFORE any FB-1 rAF-composition honoring: the ledger's "substrate ready" premise is FALSIFIED by GL-1 (S3 re-tags it), and `proof:composition` presupposes `proof:blend` green (a feature mapped onto a dead blend would be honoring a no-op) (`a-group-layering.md:213-215,234-236`).
- **HIGH, not MED — RESOLVED.** Two of three documented, UI-exposed blend modes DO NOT RUN — a real correctness bug in a shipped, UI-exposed feature, caught by no test, inverting the deferred-ledger's FB-1 premise. It is the ONE genuine net-new defect the supplemental audit surfaced (an un-assayed dimension the phase-1 gap-scorecard's lens could not see) (`_SYNTHESIS-perf-testing-engine.md §THESIS:69-90`).
