## §State, verified (file:line)

- **The rotation source of truth is a gimbal-free quaternion — ALREADY-SOTA, untouched by this wave.** `currentQuaternion = quat.create()` (`OrbitalDrag.vue:65`), "*Never reconstructed from Euler angles; only multiplied by delta quaternions*" (`:63-64`). `applyRotation` builds a delta via `quat.setAxisAngle` and left-multiplies + normalizes (`:122-131`). Angular-velocity inertia is axis+speed, not per-Euler-component (`:67-69,144-148`). This accumulation leg is the correct SOTA orbit/trackball idiom and G touches NONE of it.
- **The defect is purely on the OUTPUT leg.** `containerStyle` (`:52-60`) emits `translate3d(...) rotateX(${rotate.x}deg) rotateY(${rotate.y}deg) rotateZ(${rotate.z}deg) scale3d(...)` (`:58`) — it DECOMPOSES the gimbal-free quaternion back into three sequential Euler rotations and re-applies them as `Rx·Ry·Rz`. This is the precise quaternion anti-pattern: retrieve→modify→re-apply.
- **`quaternionToEulerDegrees` (`:74-106`, 33 lines) is the round-trip machine + its self-inflicted singularity.** It rebuilds the rotation matrix rows from the quaternion (`:75-87`), takes an `asin`-based extraction `ey = Math.asin(clamp(r02, -1, 1))` (`:89-90`), and BRANCHES on the gimbal pole: `if (Math.abs(sy) < 0.9999) { ... } else { ex = atan2(r21,r11); ez = 0; }` (`:92-99`) — the `ez = 0` fallback is gimbal-lock handling **made explicit for a problem the decomposition itself created**. The function is called from exactly two sites: the v-model sync (`:112`) — and that is its ONLY remaining caller after this wave (see §Scope S2).
- **The engine ALREADY interpolates axis-angle `rotate3d` — zero new code needed to render it.** The cube's own preset animates `transform: { rotate3d: "0, 0, 0, 0deg" } → { rotate3d: "-1, 1, 0, 30deg" }` (`useCubeAnimations.ts:95-96`), proving the parse/interp/serialize path round-trips axis-angle on `tranche-g-dev` today. CSS `rotate3d(x, y, z, angle)` consumes an axis-angle DIRECTLY — no Euler decomposition, no singularity branch, no DOF loss.
- **`quat.getAxisAngle` is already imported and is the exact inverse of the `setAxisAngle` already used.** `import { quat, vec3 } from "gl-matrix"` (`:10`); `quat.setAxisAngle` is called at `:126`. `getAxisAngle(out_axis, q)` returns the rotation `rad` via `acos(q[3])·2` and writes the NORMALIZED axis into `out_axis` (`node_modules/gl-matrix/cjs/quat.js:111-125`). At the identity quaternion (`s ≈ 0`) it returns axis `[1,0,0]`, angle `0` — which renders `rotate3d(1, 0, 0, 0deg)`, a valid no-op. The gimbal-pole singularity the Euler path branches on (`sy → ±1`) **does not exist** on the axis-angle path: `getAxisAngle` has no pole. ZERO new dependency (`a-scroll-orbital-quaternions.md:207-218,248-250`).
- **The v-model type is Euler `{x,y,z}` and stays Euler (the design call).** `TransformState.rotate: { x: number; y: number; z: number }` (`orbital-drag/index.ts:8-13`); the matrix-editor sliders and the share-state hash consume it as per-axis Euler. `clamp` (value.js, `:8`) is still used by `updateLinearTransform` (`:188`) — its import stays. The Euler convention note in `demo/CLAUDE.md` ("quaternion ↔ Euler extraction must match `Rx * Ry * Rz`") describes the v-model contract this wave preserves.

## §Goal

Collapse the orbital rotation OUTPUT to its native form: render the persistent quaternion directly as ONE `rotate3d(ax, ay, az, ${angleDeg}deg)` read off `currentQuaternion` via `quat.getAxisAngle`, and DELETE `quaternionToEulerDegrees` (33 lines incl. the gimbal branch) entirely. The quaternion is the source of truth, so the output should be the quaternion's loss-free, singularity-free native form — not a lossy three-angle re-application that re-introduces the very gimbal lock the accumulation leg was designed to avoid. Net-NEGATIVE lines, zero new dependency, zero new machinery. Per the O-1a design call: change ONLY the CSS render; the Euler v-model stays Euler for the slider/share surface (sliders are inherently per-axis Euler controls, so Euler is the right type THERE).
