# Pane Audit — motion-path scene
**Tranche J · lane: pane-motion-path**

---

## Overview

The motion-path scene is the demo's CSS-native `offset-path` shop-window: a traveller (the protagonist ball) is swept along an editable cubic B-spline by the engine's `offset-distance` sweep, with draggable control-net handles and a live `offset-path` copy artifact. The control panel is intentionally empty (`CONTROL_SURFACES["motion-path"] = []`), so the scene's sole interactive surface is the card itself.

---

## Visual Evidence — what the eye lands on

**Laptop closed** (`motion-path-laptop.png`): the glass `<Card>` fills the [stage] track. The header bar ("MotionPath" + `OFFSET-DISTANCE = 0% · TANGENT -89°` + "Reset path") sits in a thin border-b strip. The stage canvas — a soft warm-white/light-grey rectangle with a visible crosshatch grid-background showing through — fills ~75 % of the card. The dashed green path and control handles sit centred. The traveller (large green ball with emoji) is parked at the path start, left-centre. Below is the `offset-path` label + copy button + the code artifact + a centred prose description. The dock pill ("Path traversal") sits below.

**Desktop closed** (`motion-path-desktop.png`): identical composition, slightly more vertical breathing room; the stage canvas grows proportionally.

**Mobile closed** (`motion-path-mobile.png`): full-bleed fixed stage. Card fills the viewport with the path smaller in proportion. The header strip shows only `OFFSET-DISTANCE = 0%` (tangent absent), "Reset path" at far right. The code artifact is partially clipped at the bottom and the prose description is hidden below the fold, requiring a swipe that the partial-sheet scrolling affords.

**Open states** (`-open.png`): no control panel appears (empty DFA) — the dock pill changes the play icon to the group-play rainbow. The traveller moves to a mid-path position in the laptop/desktop open screenshots (the animation is playing). No panel occlusion issue by design.

## Hierarchy Analysis

**First eye landing:** the traveller ball (large, saturated green, with emoji glyph) is nominally the protagonist but only barely wins over the three large solid anchor handles (r=9, 55 % green fill) and the dashed guide path. On laptop the eye traverses: card header → guide path shape → traveller (tied) → three anchor handles → control handles → "Reset path" button. The traveller does not read as unambiguous protagonist.

**Chrome recedes:** the `Reset path` button carries full outline-variant weight and appears in the most visually legible corner of the card (top-right), drawing more attention than warranted for a secondary affordance. The `border-b` strip correctly separates it from the stage, but the button's own weight within the strip is too high relative to the telemetry readout beside it.

**Controls hierarchy:** no right-rail panel (by design). Within the card: (1) title "MotionPath" is `text-heading` — correct but there is no competing sidebar panel to differentiate from, so it could step up. (2) telemetry readout is correctly muted. (3) "Reset path" is over-weighted. (4) artifact zone is correct but dense.

## Panel-Open State

In both `-open` screenshots the dock's group-play rainbow icon has activated. The card is unchanged — no panel slides in (empty DFA). This is correct. However in the `laptop-open.png` and `desktop-open.png` the traveller has moved along the path during playback — the composition at mid-path shows the traveller inside the curve loops, which is a stronger protagonist read than the resting position (at the leftmost anchor). The resting position (traveller at `offset-distance:0%`, which maps to `M 60 200`) parks the ball near the left edge and well below the visual centre of the stage, making the composition slightly off-balance. This is not a code defect but is worth noting: the default starting position could be `0.5` to put the traveller mid-curve for the splash state.

## Summary

The motion-path scene is the demo's most mathematically expressive primitive (browser-owned geometry, tangent-following, editable cubic path) but is also its most visually timid. The protagonist ball competes equally with its own control handles. The guide path is ghost-light against the crosshatch canvas. The live telemetry (the tangent angle — the unique math of this scene) is muted chrome. The card's three-zone structure is logical but incompletely formalized. The mobile viewport truncates the tangent readout. The cyan/green split between the dock icon and the on-stage ball erodes scene identity. These are all proportionate, targetable fixes: amplify the stage field tint, fatten the guide path opacity, differentiate the telemetry text, give the `Reset path` button ghost-variant weight, and add the border-t zone separator. No structural surgery needed — this scene's mechanics are already distinctive; the visual language just needs to catch up to them.
