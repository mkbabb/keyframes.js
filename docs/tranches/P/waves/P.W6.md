### S1 — the square: valid ARIA + focus-ring + sourced keyframes + velocity-tilt/grab-pulse (D3 correctness + affordance + the kinetic egg)

**Breach.** Four D3 gaps: (a) `SquareScene.vue:37-39`'s `role="slider"` carries only `aria-label`/`aria-valuetext` — NO `aria-valuenow`/`aria-valuemin`/`aria-valuemax` (a WCAG 4.1.2 violation); (b) the `.demo-box` lacks the demo-wide `.focus-ring`; (c) `useSquareAnimations.ts`'s transport-host keyframes carry raw `#C462D8`/`#52E898` literals (the keyframe readout shows un-sourced hex — the "one identity by construction" guarantee broken); (d) the spring physics are invisible as mass — `springX.velocity`/`springY.velocity` (public, `spring.ts:250`) are read but never projected to tilt/squash (`AUDIT-DIGEST.md:728,732-734,742-744`).

**Cure.**
- **(a) valid ARIA:** bind `:aria-valuenow` to the geometric mean of `springX.target`/`springY.target` (or surface both axes as a joint 2D-slider pattern with `aria-valuemin="-1"`/`aria-valuemax="1"` per axis) — completing the slider role contract (`AUDIT-DIGEST.md:734`). The `chrome-devtools-mcp:a11y-debugging` axis: a `role="slider"` without `aria-valuenow` is an incomplete contract a screen reader misreads.
- **(b) focus-ring:** add `class="focus-ring"` to the `.demo-box` (the demo-wide contract in `design-idioms.css`) — the keyboard-reachable box gains a visible focus state.
- **(c) source the keyframe literals:** resolve the two raw hex literals in the transport-host keyframes from the same `--rainbow-*` token source `resolvePaletteSweep` uses (`AUDIT-DIGEST.md:767`) — the keyframe readout shows the token identity, not un-sourced hex.
- **(d) velocity-tilt + directional squash-stretch (the kinetic egg):** in the existing frame loop, after computing the deflection, read `springX.velocity`/`springY.velocity` and write CSS custom properties (`--spring-vx`/`--spring-vy`/`--spring-tilt`/`--spring-squash`) so the box **banks into the pull and squashes along the drag axis** — the spring made visible as mass/inertia (`AUDIT-DIGEST.md:742-744`). Add a grab-pulse `::before` ring via `@starting-style` on `.demo-box--dragging` (a one-shot "capture confirmed" tactile ring — zero JS, one `@keyframes`; `AUDIT-DIGEST.md:762-765`; `@starting-style` is Baseline 2024, degrades to no-pulse on older browsers).

**Constraint (KISS, idiomatic, no-legacy).** (a)+(b) are attribute/class additions (no machinery). (c) reuses the EXISTING token source (no new palette). (d) reads ALREADY-tracked velocity (zero new physics) and writes CSS custom properties — the transform stays a CSS-custom-property seam (no extra rAF, no extra paint authority — the L.W11 inv-ζ anti-rAF law). The grab-pulse is pure CSS (`@starting-style` + one `::before`). All token-driven (`--rainbow-*`, `--ball-tone`), never ad-hoc hex (the design-system precept — MEMORY `feedback_design_system`).

**Gate bite (S4 coverage).** `proof:spring-heatmap-navigable` carries a `square-affordance` corroborator clause: load `#/square`, assert the `.demo-box` carries `aria-valuenow`/`aria-valuemin`/`aria-valuemax` + `.focus-ring`; simulate a diagonal drag and assert `--spring-tilt`/`--spring-squash` become non-zero (the box banks). Today: no `aria-valuenow`, no `.focus-ring`, no tilt → RED.

### S2 — the spring: cure the `SpringTrace` first/last-point bug · exit the 60 Hz Vue-ref leak · add Y-containment + focus-ring (D4 correctness)

**Breach.** Three D4 correctness/perf defects: (a) `SpringTrace.vue:50-86`'s `linear()` parser anchors `pts[0].pct = ?? 0`/`pts[n-1].pct = ?? 100` AFTER the null-pct fill loop (`:77-79` after `:62-74`) — so the first/last SVG points get wrong x-coordinates (the CSS `linear()` spec mandates first=0%/last=100% by definition — `AUDIT-DIGEST.md:777-779`); (b) `useSpringHotPath.ts:80` `scrubberPhase = ref(0)` is written at 60 Hz (`:143`) and read in a `SpringScene.vue:113` slot render → the ribbon functional component re-renders 60×/s (a reactive hot-path leak — `AUDIT-DIGEST.md:780-782`); (c) `useSpringPaneDrag.ts` clamps X but not Y, and `SpringTarget.vue:64`'s `role="slider"` rail lacks `.focus-ring` (`AUDIT-DIGEST.md:814`).

**Cure.**
- **(a) the trace bug — root cure (preferred):** add a first-class `springLinearStopsArray({response, dampingFraction, sampleCount?})` to the LIGHT barrel returning `[{v, pct}]` stops (the array is ALREADY computed at `src/animation/springLinearStops.ts:63-68` before the CSS-string format — a ~5-10 LoC refactor). `SpringTrace.vue` consumes the typed array directly — **no inline parser = no wrong-pct bug** (`AUDIT-DIGEST.md:789-792`). The minimal correctness FLOOR (if the LIGHT API addition is deferred to P.WZ): anchor `pts[0].pct = 0`/`pts[n-1].pct = 100` BEFORE the fill loop (`SpringTrace.vue:55`) — the in-place cure (`AUDIT-DIGEST.md:779`).
- **(b) exit the 60 Hz Vue-ref leak:** move `scrubberPhase` out of the reactive graph — replace the `ref(0)` with a non-reactive number on the `springLive` snapshot and register a DOM-direct painter (`registerScrubberPainter(cb)`) writing the glass-ui Slider position imperatively, so the ribbon's render effect is NOT triggered 60×/s (`AUDIT-DIGEST.md:782,793-795`). The position channel becomes a painter, like the ball-position hot path the registry already proves.
- **(c) Y-containment + focus-ring:** in `useSpringPaneDrag.ts` `applyTransform()`, compute `laidOutTop = rect.top - offsetY` and clamp `offsetY` to keep the pane in the viewport vertically (`AUDIT-DIGEST.md:814`); add `class="focus-ring"` to the `SpringTarget.vue:64` rail.

**Constraint (correctness-first, no-legacy, dogfood).** (a) prefers the gestalt root cure (the LIGHT `springLinearStopsArray()` API eliminates the parser class entirely) with the in-place anchor as the minimal floor — no parser left beside the new API (no-legacy). (b) exits Vue's reactive graph for the 60 Hz channel (the hot-path discipline the painter registry already established — MEMORY `AnimationGroup / Vue Reactivity`). (c) is a clamp + a class. The `springLinearStopsArray()` addition is LIGHT (value.js-free — `springLinearStops.ts` is a LIGHT static export per `CLAUDE.md`); it does NOT pull value.js onto the demo's light path.

**Gate bite (S4 coverage).** `proof:spring-heatmap-navigable` carries a `trace-correct` clause: assert the `SpringTrace` first SVG point has `x === 0` and the last has `x === 100` (the `linear()` anchor invariant) for an overshooting spring; and a `scrubber-non-reactive` clause: via MutationObserver, assert the ribbon root's subtree does NOT re-render at 60 Hz during scrub.
