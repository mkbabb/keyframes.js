## §Goal

Replace the five-authority lattice + the three competing playback authorities + the `isStableFire` double-fire heuristic with ONE `useSceneMachine()` (`createGlobalState` + a pure `transition(state, event)` reducer; states `idle | loading | playing | paused | suspended`) that OWNS the active-scene fact and the per-scene playback snapshot — done in ONE motion, the replaced surfaces *replaced*, not aliased beside (the spine: NO legacy beside its replacement). **The route is NOT a projection — it is an EXTERNAL input (ownership inversion, WV-W1-HIGH-2):** the browser owns the URL via popstate (the storm's FIRST nav is always `popStateHandler`), so a pure reducer cannot OWN `activeScene` without a reconcile rule. The route is reconciled via ONE `afterEach`/popstate→`NAVIGATE` READER + ONE `NAVIGATE`→`push` WRITER + an `activeScene`-equality echo guard (the writer no-ops when the route already matches, breaking the feedback loop). The dock Select model, the `?anim=` param, and localStorage ARE one-way **read-only projections** of `machine.activeScene` (they can never write back into scene selection); the route is the one external input the machine reconciles, not a projection it owns. Home and cube become DISTINCT states (home = no group, cube = its group — killing the alias). Suspend/restore becomes a declarative IDENTITY: a leave SUSPENDs (stops the active rAF, snapshots from the ONE authority), a `SCENE_READY` event RESTOREs on exactly one explicit transition (no remount race). Deep-link wins over localStorage. The deprecated `next()` drops to a returned value. The engine `AnimationGroup.serialize()/hydrate()` seam (the value-side of the demo) is named as a born-RED HANDOFF: the store lands FIRST against the existing imperative restore, then swaps to the engine API when it ships. This is the architectural transposition the spine names NECESSARY AND DESIRABLE — fewer composables (six → two/three), one source of truth per axis, the route storm and the corrupt panel and the orphaned rAF all DELETED by the single move.

## §Design decisions (trade-offs RESOLVED)

- **`createGlobalState` + reducer, NOT Pinia — RESOLVED (the §2.1 adjudication, BINDING).** 2-of-3 D12 lanes favor `createGlobalState`+a hand-rolled reducer; the dissent's strongest point (devtools time-travel, persist plugin) is real but does not outweigh the spine's no-parallel-system rule. The demo ALREADY standardizes on `createGlobalState`+`@vueuse/core`; Pinia means EITHER a transitional period with both paradigms (no-legacy violation) OR porting all 6 stores + 30 call-sites in one motion AND a runtime dep — a larger, riskier transposition whose only unique wins are achievable here (`@vueuse/useStorage` = persistence). The user's *named choice* (a formal store + state machine) is honored in SPIRIT — the FSM is the deliverable, not the library. Pinia is BOOKED if a future tranche measures a genuine devtools/persist need createGlobalState cannot meet (`_SYNTHESIS-gap-scorecard.md:92-105`).
- **A pure reducer, NOT XState — RESOLVED.** `@vueuse/core@14.3.0` does NOT export `useStateMachine` (grep empty — `a-store-architecture.md:86`); full XState is overkill (~15KB, actor model). A ~40-line hand-rolled `transition(state, event) → state` pure function is the "XState-lite" the lanes gesture at — zero new runtime dep, fully unit-testable as a pure function (`a-store-architecture.md:87`; `a-demo-architecture.md:173-185`).
- **The lever is an explicit capture/restore contract, NOT flipping KeepAlive back — RESOLVED.** KeepAlive-vs-remount is NOT the lever (it broke the async loader — `App.vue:110`; keep the bare `<Suspense>`); the lever is an EXPLICIT capture/restore contract that does not depend on component-instance survival (`a-engine-regressions.md:228-230`). EACH scene round-trips its OWN full state via a contract method; the placeholder-`contractAnim` pattern is the smell — it makes `useSceneGroupSync` think it preserves state when it preserves nothing (`a-engine-regressions.md:218-223`).
- **The route is an EXTERNAL INPUT reconciled (ONE reader + ONE writer + echo guard), NOT a projection — RESOLVED (WV-W1-HIGH-2, ownership inversion).** The browser OWNS the URL via popstate (the storm's first nav is always `popStateHandler`) — so the original "route = read-only one-way projection of `machine.activeScene`" INVERTED ownership: a pure reducer cannot own `activeScene` without a reconcile rule for popstate. The route is reconciled via ONE `afterEach`/popstate→`NAVIGATE` reader + ONE `NAVIGATE`→`push` writer + an `activeScene`-equality ECHO GUARD (the writer no-ops when the route already matches). The dock model, `?anim=`, and localStorage ARE one-way projections (they can never write back into scene selection); the route is the one external input the machine reconciles. This kills the feedback loop at the source (S3) — not by debouncing harder or adding more gen-guards (workarounds), but by the echo-guarded single-writer reconcile (`a-scene-state-machine.md:218-220`).
- **Two orthogonal axes (scene ∈ 9, playback ∈ 5), not one flat enum — RESOLVED (CP-LOW-4 wave-half).** The S1 enum framing conflated two axes: the SCENE axis (9 scenes) and the PLAYBACK axis (5 states `idle|loading|playing|paused|suspended`). The reducer's `state` is the playback axis; `context.activeScene` is the scene axis — they are orthogonal (matches `a-demo-architecture F3`). The `perScene` snapshot map keys the playback axis BY the scene axis; a scene switch and a play/pause are distinct events.
