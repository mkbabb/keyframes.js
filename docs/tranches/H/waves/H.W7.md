## §Goal

Make mobile stop STACKING and start OVERLAYING — the same `rail·stage·rail` grid (H.W3) re-parameterized so the animation IS the full-bleed background and the controls are a `SpringProgress`-driven bottom sheet over it. ONE rebuild (F1+F2 are one motion): (1) the stage layer becomes `position: fixed; inset: 0` (behind the docks, z below `z-controls`), honoring `--work-area-top-offset`/`--dock-band-reserve` so the subject parks in the dock-free band and is ALWAYS visible — the literal background the user asked for; (2) the controls pane becomes a bottom SHEET anchored above the bottom menubar, sliding up OVER the stage (the cube stays visible — and, per F4/D11, draggable — behind a partial sheet); (3) the `grid-rows-[auto_1fr_auto]` mobile branch is DELETED, not patched — the desktop `1fr` full-bleed stage becomes the single stage model; the sheet's open/closed transform is the ONLY mobile-specific delta (a named, befitting delta — KISS/DRY); (4) the teleport-timeline (`row-start-3`) folds into the sheet's scroll body or a second sheet detent — it must NEVER re-introduce a third consuming row; (5) the sheet's open/close motion is driven by a `SpringProgress` instance (a `useSheetSpring(open)` composable mirroring `useSceneSwap`), snappy preset (`response≈0.3, dampingFraction≈0.8`), settle <350ms, `respectReducedMotion: true` for the single-frame PRM snap — the 550ms CSS `grid-template-rows` ease is DELETED. The docks need no structural change — only their z-order must sit ABOVE the new fixed stage (verify no `z-dock`/`z-controls` inversion). This transitively delivers the single-page, contextual, interactive mobile the user asked for, and unlocks mobile cube-drag for free (F4/D11). Net-DELETION of a divergent code path; the demo re-acquires a demo-owned spring on its own chrome. KISS · DRY · no second landlord · dogfood-as-mandate.

## §Design decisions (trade-offs RESOLVED)

- **Overlay, not a shorter stack — RESOLVED (the architectural transposition).** D10 is NOT a styling nudge; the mobile grid is a STACK that structurally CANNOT make the animation the background (the `auto` row1 starves the `1fr` row2 to ~0). The gestalt move is to DELETE the mobile branch and make mobile do what desktop already does (overlay) — removing a divergent code path, not adding one. A shorter stack or a capped pane height would still stack; only the overlay makes "background = animation" possible (`a-mobile-architecture.md:88-117`).
- **Dogfood `SpringProgress`, not a shorter CSS duration — RESOLVED (D13).** The drawer is the demo's most-visible structural motion and the ONLY major motion still on a hand-rolled CSS curve. Shortening the 550ms is the quick fix the spine forbids and re-forks the motion story. The product IS a spring engine; emit a `linear()`/drive a `SpringProgress` from the engine into a demo-owned token (the `StartingStyleTarget.vue:94` precedent) — purer dogfooding than swapping a library spring, because the drawer is BESPOKE (not vaul/Sheet) (`a-mobile-architecture.md:128-147`; `a-animations-quality.md:133-145`).
- **No second landlord — emit into a demo-owned token, leave glass-ui's family alone — RESOLVED.** The desktop `--spring-snappy: var(--spring-smooth)` alias is a FOREIGN (glass-ui) token; the demo deleted its own emission in D.W11. The fix re-acquires a DEMO-OWNED spring on the chrome (emit from the engine, name the delta) while staying coherent with glass-ui's family — do NOT re-introduce a parallel landlord. Whether glass-ui exposes a "snappy fast" member is glass-ui's call (HANDOFF) (`a-animations-quality.md:140-145`).
- **The sheet re-uses H.W3's `--rail-width`; no stale `440px` cap — RESOLVED.** H.W7 is sequenced AFTER H.W3 so the bottom sheet's width is the SAME single `--rail-width` authority, not a re-forked `max-width: min(440px, 100dvw)`. The stale cap (`ControlsPaneWrapper.vue:215-219`) is folded into the sheet styling (full-bleed width, internal padding) and verified on a 430-wide device (iPhone Pro Max logical 430) so the sheet does not float oddly (`a-mobile-architecture.md:231-241`).
- **The teleport-timeline NEVER re-introduces a third row — RESOLVED.** The `row-start-3` expanded-timeline teleport (`AnimationControlsGroup.vue:66`) folds into the sheet's scroll body or a second sheet detent — it must not become a third consuming row that re-starves the stage. The single stage model has exactly one stage and one sheet (`a-mobile-architecture.md:104-106`).
- **The docks are ALREADY-SOTA — only z-order is touched — RESOLVED.** The affixed fixed docks with safe-area insets + `@supports not (dvh)` fallbacks are exemplary scaffolding (F3); the rebuild changes NO dock structure — only verifies the new `fixed` stage sits z-below the docks and does not steal the menubar's pointer events. Re-touching exemplary scaffolding is the inverse failure (`a-mobile-architecture.md:160-188,268-271`).
- **F1+F2 are ONE rebuild — RESOLVED.** The full-bleed stage and the spring sheet are not two workstreams: the sheet's spring transform IS the mobile-specific delta on the overlay model. They co-land (the spine's "one motion"); the z-order verification (S3) is part of the F1 rebuild, not a sequel. F4 (mobile interactivity) is UNLOCKED by the rebuild but designed in D11's lane.
- **Sequenced after H.W3, independent of H.W1/H.W6 — RESOLVED.** H.W7's overlay re-parameterizes H.W3's single named grid — it MUST follow H.W3 to re-use the one `--rail-width` authority. It has no dependency on the FSM (H.W1) or the dots (H.W6); the drawer-spring half is a kf-local dogfood swap that co-lands with the overlay.
