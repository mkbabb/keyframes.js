## §Design decisions (trade-offs RESOLVED)

- **Overlay, not a shorter stack — RESOLVED (the architectural transposition).** D10 is NOT a styling nudge; the mobile grid is a STACK that structurally CANNOT make the animation the background (the `auto` row1 starves the `1fr` row2 to ~0). The gestalt move is to DELETE the mobile branch and make mobile do what desktop already does (overlay) — removing a divergent code path, not adding one. A shorter stack or a capped pane height would still stack; only the overlay makes "background = animation" possible (`a-mobile-architecture.md:88-117`).
- **Dogfood `SpringProgress`, not a shorter CSS duration — RESOLVED (D13).** The drawer is the demo's most-visible structural motion and the ONLY major motion still on a hand-rolled CSS curve. Shortening the 550ms is the quick fix the spine forbids and re-forks the motion story. The product IS a spring engine; emit a `linear()`/drive a `SpringProgress` from the engine into a demo-owned token (the `StartingStyleTarget.vue:94` precedent) — purer dogfooding than swapping a library spring, because the drawer is BESPOKE (not vaul/Sheet) (`a-mobile-architecture.md:128-147`; `a-animations-quality.md:133-145`).
- **No second landlord — emit into a demo-owned token, leave glass-ui's family alone — RESOLVED.** The desktop `--spring-snappy: var(--spring-smooth)` alias is a FOREIGN (glass-ui) token; the demo deleted its own emission in D.W11.
