## §Goal

Make the demo's default landing scene (`#/cube`) and every home↔scene transition produce **zero console errors** — the prerequisite that lets every visual H lane measure a clean console. Two contained fixes, each at the higher altitude the spine demands:

1. **H-A1 (engine-faithful, the DRY answer):** the Cube preset animations that use closure easings get faithful `Easing.css` twins (a `cubic-bezier()` / `linear()` literal) at construction. Then `serializeEasing` round-trips losslessly — G.W4's fail-explicit policy is **satisfied, not swallowed** (the curve flows through the type system as `{ fn, css }`, the W4 design intent). The readout never throws because the value IS serializable. A `try/catch` neutering of the readout is the *fallback* altitude (consumer-faithful: render a `/* timing-function: custom */` comment placeholder), NOT the preferred fix, and is taken ONLY for any preset whose closure has no faithful CSS twin. Do NOT re-introduce the silent `"linear"` degrade (that was the bug W4 fixed).
2. **H-A2 (engine, the idiomatic deeper fix):** the compile/interp pipeline classifies a leaf whose value is a non-numeric, non-color, non-unit STRING as a **discrete (hold-then-snap)** leaf — interpolate by snapping at the segment midpoint rather than handing it to value.js `_lerp`. The hero ellipsis never aborts a frame; a `{label:"a"}→{label:"b"}` corpus row snaps discretely with no throw. (If the parse lives entirely inside value.js's `_lerp`/`flattenObject`, the discrete-classification is a **value.js-HANDOFF** RECORD; the engine-side `processFrame` guard is the kf-side belt-and-suspenders that lands in H regardless.)

KISS · DRY · no new machinery. The crashes die; the engine becomes "interpolate ANYTHING" in fact, not just in headline. This is a **shipped-product-correctness** fix: 4.1.0 throws on its own default scene.

## §Design decisions (trade-offs RESOLVED)

- **The `.css` twin is the fix, not a readout `try/catch` — RESOLVED.** The tempting quick fix is to wrap the `KeyframesStringControls.vue:94` readout in `try/catch` and call it done. That swallows G.W4's fail-explicit signal — the curve is silently un-serializable and the editor tab stays empty (`a-engine-regressions.md:68-72`). S2's readout guard is the FLOOR for a genuinely non-representable curve (placeholder comment, never silent `"linear"`), not the primary.
- **The discrete-leaf classification is the CSS-correct behaviour, not a swallow — RESOLVED.** S3 does NOT silently drop the leaf or coerce it to `"linear"`; it implements the CSS discrete-animation rule (hold-then-snap at the midpoint) for non-interpolable strings — the spec-faithful behaviour for `content`/keyword properties (`a-engine-regressions.md:139-147`). The gate (c) asserts the EXACT discrete snap, so "discrete" is a tested contract, not a hand-wave.
- **value.js-HANDOFF vs kf guard — RESOLVED (both, sequenced).** The deeper classification may belong in value.js (where the parse happens). H.W0 lands the kf-side `processFrame` guard NOW (the belt-and-suspenders, demo unblocked immediately) and RECORDs the value.js classification as a HANDOFF that rides the next re-pin; the corpus row (c) is the consume-signal that stays green either way (`a-engine-regressions.md:144-147,345-348`). - **Sequenced FIRST, parallel to H.W1 — RESOLVED.** H.W0 is a prerequisite: the live crashes poison every other lane's clean-console measurement (`_SYNTHESIS-gap-scorecard.md §3`).
