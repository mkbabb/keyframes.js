# A.W2 — Boundary ergonomics

**Phase:** IMPLEMENTATION · **Status:** LANDED

The value.js boundary the package is carved along (light static engines · the heavy
`engine.ts` reached only through `await import("./engine")`) was sound but shipped two
ergonomic seams open: a string easing *name* interpolated silently-linear until it
resolved, and the `.ready()` dance that drives that resolution was hand-threaded three
times with no shared contract. W2 collapses both into one resolver—`EasingResolvable`—
closes the silent window with eager-resolve-on-construct plus a dev-only signal for the
residual, and keeps the light bundle's static graph value.js-free.

## What landed

### `EasingResolvable` — the one shared string-easing-name resolver

`src/animation/internal/easing-resolvable.ts` (NEW). The light engines accept easing as
EITHER a callable `TimingFunction` (value.js-free, used directly) OR a string easing
*name* from value.js's registry (`"ease-out-cubic"`, `"easeOutCubic"`, …). A name can
only be resolved through the heavy engine—value.js owns the easing registry—so resolution
rides the dynamic `import("../engine")`: the single value.js edge, taken once, lazily,
only when a named easing is actually used. `EasingResolvable` is that contract, in one
place:

- **callable easing** → resolved synchronously at construction; `.fn` is the callable,
  `.ready()` is a no-op, nothing is imported (easing-resolvable.ts:54-56).
- **string name** → `.fn` is the identity fallback until resolution lands; resolution is
  kicked off EAGERLY in the constructor (`void this.ready()`, easing-resolvable.ts:64).
- **omitted** → identity fallback, never pending (easing-resolvable.ts:65-67).

Surface:

- `.fn` — the live easing: the resolved callable, or the identity fallback while a name
  is pending (easing-resolvable.ts:71-73).
- `.pending` — true while a string name has not yet resolved (easing-resolvable.ts:76-78).
- `.ready()` — memoized; the `await import("../engine")` + `getTimingFunction` lookup run
  at most once per instance; a resolved promise for callable/omitted easing
  (easing-resolvable.ts:86-102).
- `constructor(easing, onResolved?)` — `onResolved` fires once when a pending name lands,
  for consumers that cache the easing **by value** (`NumericAnimation` rebuilds its
  segments). Consumers that read `.fn` **live** each frame (`Timeline`) pass no callback
  (easing-resolvable.ts:48-52).
- `.warnIfPending(context)` — the dev-only signal (below).

Value.js-free by construction: the module imports value.js NOWHERE statically—only the
dynamic `import("../engine")` inside `ready()` reaches it, and `import type` on `TimingFunction`/
`TimingFunctionNames` is erased under `verbatimModuleSyntax`. A light-only consumer's
static graph never pulls value.js in.

### The silent-linear footgun, closed

Before: a string name set `timingFn = linear` and parked the name for lazy resolution on
the first `.play()`/`.ready()`. A stateless consumer who passed `"easeOutCubic"` and never
awaited `.ready()` got silently-wrong curves on the first frames—the wrong-until-ready
window with nothing surfacing it (the binding-verification class: types pass, runtime
quietly differs).

W2 closes it in two layers:

1. **Eager-resolve-on-construct (the primary fix).** A string name kicks off resolution in
   the constructor (`void this.ready()`), so the named curve lands by the first frame—the
   import is async, but it is started at construction rather than deferred to first
   `.play()`. The silent window shrinks from "until you explicitly await" to "a same-tick
   synchronous `.at()`/`tick()` before the microtask resolves." `await .ready()` remains
   the opt-in for a consumer that needs the eased value on the very first synchronous read.
2. **`warnIfPending(context)` makes the residual DETECTABLE (the dev signal).** A
   synchronous read of the easing while a name is still pending interpolates with the
   identity fallback—`warnIfPending` emits a ONE-time `console.warn` naming the context and
   the pending easing (easing-resolvable.ts:116-126). One-time per instance: every-frame
   noise is useless. It is befitting-silent-with-rationale, not a thrown contract violation:
   this is a browser-timing degradation hint, not a library-internal failure (those throw).
   Production strips it entirely—the published bundle's `esbuild.drop: ["console"]` removes
   the call, so it is genuinely dev-only and carries zero ship cost.

`NumericAnimation.at()` calls `warnIfPending("NumericAnimation.at()")` (numeric.ts:170);
`Timeline.applyPipeline()` calls `warnIfPending("Timeline.tick()")` (timeline.ts:82).

### The three hand-rolled `.ready()` copies, retired

The resolution dance lived three times with no shared contract. W2 relocates it into the
one resolver—a net deletion, not an alias:

- **`numeric.ts`** — DELETED its local `linear` fallback, its `prefersReducedMotion()`
  copy (the latter relocates in W4), its `timingFn` field, its `_pendingEasingName` /
  `_easingReady` state, and its hand-rolled `ready()` body (the `import("./engine")` +
  `getTimingFunction` + segment-rebuild). It now holds one `EasingResolvable` field
  (numeric.ts:78), passes the segment rebuild as the `onResolved` callback
  (numeric.ts:98-100), reads `this._easing.fn` when building a segment (numeric.ts:140),
  and delegates `ready()` to it (numeric.ts:156-158). Segments capture the easing by value
  at build time, so the callback rebuilds them on resolution.
- **`timeline.ts`** — DELETED its `easingFn` field, its private `resolveEasingName()`, and
  its `_easingReady` memoize. It holds one `EasingResolvable` field (timeline.ts:41),
  constructs it with no callback (timeline.ts:48), reads `.fn` LIVE each tick in
  `applyPipeline` (timeline.ts:87), and delegates `ready()` (timeline.ts:66-68). Reading
  `.fn` unconditionally is a no-op for the omitted-easing case—`.fn` is identity until a
  name resolves.
- **`morph.ts`** — already composes `NumericAnimation` and delegates `ready()` to it
  (morph.ts:94-96). It carried no resolver copy of its own, so it inherits the new contract
  for free: no W2 edit. The three call sites resolve to two consumers plus one delegate.

## Boundary preserved

The light bundle keeps a zero static value.js edge: the resolver's only value.js reach is
the dynamic `import("../engine")` inside `ready()`, and eager-resolve moves only the
*trigger* of that import earlier—it does not make the edge static. `dist/keyframes.js`
remains the ~17 KB value.js-free barrel; the value.js-bearing easing registry lands in the
~26 KB `engine-*.js` dynamic chunk only when a named easing is used. `proof:boundary`
(A.W3) is green—0 value.js modules in the light entry chunk.

## Precept compliance

- **No backwards-compat aliases.** The `.ready()` unification RELOCATES the shared logic—
  it does not keep the three copies for safety. The silent-linear remediation changes
  behaviour at the construct/`.at()` boundary cleanly; no compatibility flag.
- **Overfitting / substrate-without-consumer.** `EasingResolvable` has three consumers
  (`numeric` + `timeline` directly, `morph` via `numeric`) and is a net deletion of two
  hand-rolled copies—de-duplication, not speculative surface. Clears trivially.
- **Fail-explicit vs befitting-silent.** A value.js-internal resolution failure is
  library-owned (the engine path); the dev-warn is a browser-timing degradation hint and
  stays silent-with-rationale, stripped from production.
