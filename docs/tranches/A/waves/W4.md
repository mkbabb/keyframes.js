# A.W4 — Engine modern-web/perf pass

The engine's own modern-web identity. The KF-B1 boundary framed keyframes only as
the value.js gate; this wave gives the engine a posture of its own—reduced-motion
on every play path (not just the light opt-in interpolators), `scheduler.yield()`
in the group compositor for INP relief, and the spring curve carried onto the WAAPI
compositor instead of flattened to `linear`. Each lever ships only where a
consumer-backed need exists; the headless-engine spine items with no lever are
refuted in the record, not invented.

The applicable modern-web spine collapses to **perf/INP + motion/VT** (A.md
§Modern-web spine mapping); both fold here.

## What landed

### The shared reduced-motion gate — `internal/reduced-motion.ts` (3 dup decls → 1)

`internal/reduced-motion.ts` is the ONE `prefersReducedMotion()` for the whole
engine—a single SSR-safe authority that returns `false` off-DOM (no `window` /
`matchMedia`) so a consumer never guards the call. The three hand-rolled copies
(one each in `numeric.ts`, `smooth.ts`, `spring.ts`) are deleted; `smooth.ts:5`
and `spring.ts:5` re-import the shared gate (net deletion, no aliases per the
no-legacy precept).

**WHY:** PRM is a Widely-available platform query; three byte-identical detectors
is a maintenance seam and a drift risk. Collapsing them gives glass-ui /motion one
detector to fan the heavy-surface PRM posture out across the constellation from.

### The exported `RAFPlayback` PRM gate (light managed-playback surface)

`RAFPlayback` (`playback.ts`)—the exported shared playback primitive for the light
interpolators—now OWNS the reduced-motion snap. `play(duration, onTick, {
respectReducedMotion })` fires `onTick(1)` exactly once and resolves on the next
microtask under an active `prefers-reduced-motion: reduce` query—no rAF loop is
spawned (`playback.ts:70-73`). `NumericAnimation.play()` (`numeric.ts:81`,
`_playback = new RAFPlayback()`) routes its snap straight through here, and
`ElementMorph` inherits it by composing `NumericAnimation`.

**WHY:** the snap lives in ONE place rather than re-implemented per interpolator;
exporting it means a consumer driving its own light playback gets the same gate.

### Heavy `Animation.play()` + `AnimationGroup` PRM snaps

The heavy engine carries a richer lifecycle (iteration, direction, fill, events)
that doesn't factor into `RAFPlayback`, so it carries its own snap:

- **`Animation`** — `AnimationOptions` gains `respectReducedMotion`
  (`constants.ts:99,121`, default `false`) + `setRespectReducedMotion()`
  (`engine.ts:485`). `play()` checks `respectReducedMotion && prefersReducedMotion()`
  FIRST—reduced-motion wins over WAAPI and rAF (`engine.ts:787`)—and routes to
  `_playReducedMotion()` (`engine.ts:765`): `animationstart` → `fillForwards()` →
  `done` → `animationend`, no rAF/WAAPI loop. The lifecycle stays observable so a
  consumer's event wiring is identical to a completed normal play; the visual lands
  on the same end state a forwards fill settles on.
- **`AnimationGroup`** — `respectReducedMotion` field (`group.ts:54`, default
  `false`) + `_playReducedMotion()` (`group.ts:439`): advances every child to its
  final frame, composites a single paint for single-target groups
  (`transformFramesGrouped`), then settles through the same `reset()` the normal
  draw-completion path runs—no rAF loop, no motion.

**WHY:** the heavy `Animation`/`morph`/`timeline`/group play paths were the
constellation's heavy-surface PRM hole (every glass-ui /motion surface wrapping
them animated fully under `reduce`). The gate closes it from one detector.

### `scheduler.yield()` — `internal/scheduler.ts` + `group.tick()` batching (INP)

`internal/scheduler.ts` exports `yieldToMain()` (≤20 LOC): native
`scheduler.yield()` when present (continuation at the FRONT of the task queue, so
yielding stays cheap) → `MessageChannel` macrotask → `setTimeout(0)`. Strategy is
feature-detected per call, not cached, so the active scheduler is always honored.
SSR-safe—resolves immediately off-DOM.

`AnimationGroup.tick()` (`group.ts:340`) ticks children in batches of
`AnimationGroup.YIELD_BATCH = 32` (`group.ts:62`). Groups at or under that size
tick in ONE slice (the fast path, no yield); larger groups tick batch-by-batch with
a `yieldToMain()` between batches (`group.ts:356-361`) so a big per-frame composite
doesn't run as one long task.

**WHY:** `AnimationGroup.tick()` was the one hot loop the whole constellation drives
through (glass-ui /motion → fourier/muster/words; speedtest canvas; slides). A large
group composited as a single `await Promise.all` over every child was one
main-thread long task per frame with no INP relief. Baseline-Newly: `scheduler.yield()`
native, ≤20 LOC progressive fallback per the Baseline browser policy. This is the
engine-internal sibling of glass-ui's shipped `useYieldToMain`—same scheduler
authority, no shared module (keyframes is upstream of glass-ui).

### WAAPI spring `linear()` widening — **LAND** (css-easing tag + emission)

The verdict A.md left as land-or-refute lands. A `TimingFunction` is an opaque
`(t) => number`; the WAAPI delegation path cannot recover a CSS easing string from
it—so when a closure HAS a faithful CSS representation, it is tagged:

- **`internal/css-easing.ts`** (NEW) — `tagCSSEasing(fn, css)` /
  `getCSSEasing(fn)` read & write a `TimingFunction`'s CSS easing string via
  `Symbol.for("keyframes.cssEasing")`. Value.js-free (a `Symbol` + an erased type
  import); living in `internal/` lets the LIGHT producer (`springTimingFunction`)
  and the HEAVY consumer (`waapi.ts`) share the tag without coupling their modules.
- **`springTimingFunction`** (`springTimingFunction.ts:113`) — tags its sampled
  closure with `springLinearStops(stopOpts)`, the `linear()` string from the SAME
  solver it samples (`springTimingFunction.ts:107-113`). The JS easing and the CSS
  string describe ONE curve.
- **`waapi.ts`** — `toWAAPIOptions` reads frame 0's uniform timing function and
  emits `getCSSEasing(uniformTiming) ?? "linear"` as
  `KeyframeEffectOptions.easing` (`waapi.ts:169-171`)—the spring's `linear()` when
  present, bare `linear` otherwise. `getTimingFunction` returns closures unchanged
  (utils), so the tag survives onto `frames[].timingFunction` and reaches the
  emission point.

**WHY:** a spring `Animation` delegated to WAAPI previously ran the compositor at
`linear`, silently losing the damped-spring overshoot/settle on the one path that
would put it on the compositor thread. The producer (`springLinearStops`) and the
consumer field (WAAPI `easing`) both already shipped—this is wiring, not net-new
substrate. `isWAAPIEligible` gates on direction/fill/target shape, not easing, so
spring-eased WAAPI animations DO occur; the refute-condition ("no spring-eased
animation is ever WAAPI-eligible") is false. The constellation's three spring
surfaces—CSS `linear()` tokens, the WAAPI compositor curve, the JS easing—are now
provably one solver.

## Deferrals (recorded honestly)

- **The dev-only LoAF observer (grand-audit §2.4) is NAMED-FORWARD.** A
  `PerformanceObserver({type:'long-animation-frame'})` would make the yield work's
  measurement causal rather than anecdotal—but there is no wired CI/demo consumer to
  verify it here. Shipping a `PerformanceObserver` hook with no consumer violates the
  overfitting precept (≥2 consumers or a demo). Named-forward, not shipped.
- **The Playwright `>50ms`-trace gate (A.md A.W4) is NOT run here.** That gate
  requires a browser bench run (`bench/playwright.bench.ts`) not executed in this
  pass. The yield is **unit-verified instead**: `test/engine-modern-web.test.ts`
  proves a large group (`> YIELD_BATCH`) yields between batches and a small group
  (`≤ YIELD_BATCH`) does not (the fast path). The trace gate is the browser-level
  confirmation of the same property the unit test asserts.

## Refuted spine items (no consumer-backed lever for a headless engine)

- **CSS-platform** — keyframes owns no stylesheet; its CSS surface is the parsed
  `@keyframes` input grammar, not platform utilities.
- **CWV/content-visibility** — a consumer-DOM concern; the engine renders no
  document.
- **forms/a11y** — no form, no ARIA surface; a11y for keyframes reduces to
  reduced-motion, folded above.
- **security/PWA** — no server, no service-worker; the supply-chain analogue (the
  value.js boundary, `sideEffects: false`, publish provenance) is covered by A.W1 +
  A.W3.

## Hard gate + evidence

- **Reduced-motion snaps on every path under the media query** — `RAFPlayback`
  `onTick(1)` once with no rAF loop; heavy `Animation.play()` snaps to the final
  frame (`opacity → 1`) with no rAF; `AnimationGroup.play()` resolves without an rAF
  loop. Verified in `test/engine-modern-web.test.ts`.
- **`scheduler.yield()` breaks large-group tasks** — `yieldToMain()` prefers native
  `scheduler.yield()`, falls back to a macrotask; a large group yields between
  batches, a small group does not. Unit-verified (the Playwright `>50ms` trace is the
  deferred browser-level confirmation of the same property).
- **WAAPI spring `linear()` emission** — `springTimingFunction` tags its closure
  with a `linear(`…`)` string (without changing the closure's numeric behavior:
  `tf(0) === 0`, `tf(1) === 1`); `toWAAPIOptions` emits that string for a
  spring-eased animation and bare `"linear"` for an untagged easing.
- **Test evidence:** `test/engine-modern-web.test.ts` — **15 tests** (RAFPlayback
  PRM gate, heavy `Animation` PRM snap, group PRM snap, `yieldToMain` + group
  batch-yield, WAAPI spring `linear()` emission). Part of the 286-test suite (was
  260; +26 across the tranche).
- **The boundary holds:** the new `internal/` modules are value.js-free
  (`reduced-motion.ts` reads only `window.matchMedia`; `scheduler.ts` only the
  global `scheduler`/`MessageChannel`; `css-easing.ts` a `Symbol`), so the light
  bundle stays value.js-free and `proof:boundary` (inv α) stays green.
