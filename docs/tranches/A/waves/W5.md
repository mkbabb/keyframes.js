## § π — build-verification floor (library-not-visual)

keyframes.js is a headless animation engine. It mounts no document, lays out no
pixels—its product is `dist/`, not a rendered surface. So A's close does not
carry a paired pixel-π: there is no open/close screenshot baseline to diff
because A ships no pixel-layout delta. A's deltas are **static-graph** (the
boundary's value.js byte count), **behavioural** (the reduced-motion snap), and
**perf** (the long-task break under `scheduler.yield()`). None of these is a
pixel.

The build-verification floor stands in for pixel-π. It is GREEN when:

- **286 tests pass** (`npm test`)—the regression bar. A-open carried 260; W2
  added the 11-test `easing-resolvable.test.ts`, W4 the 13-test
  `engine-modern-web.test.ts` (+26 net). The light/heavy boundary's behaviour,
  the eager-resolve window, the reduced-motion snap on every path, the
  `scheduler.yield()` batch break, and the WAAPI spring `linear()` emission are
  all under test.
- **`check:lib` clean** (`tsc --noEmit -p tsconfig.lib.json`)—the library
  type-checks with zero demo-only `@mkbabb/glass-ui/dock` type gap (W1).
- **`build:lib` succeeds** (`vite build --mode production`)—the publishable
  artefact builds with `../glass-ui` absent (inv β). The boundary holds on disk:
  `dist/keyframes.js` ~17 KB value.js-free barrel, `dist/engine-*.js` ~26 KB

- **`proof:boundary` green** (`node scripts/proof-boundary.mjs`)—the spring-only

The full clean-runner chain—`npm ci && npm run check:lib && npm run build:lib &&

### π-lane skip justification (adoption fold §3)

The constellation visual-evidence protocol binds a tranche to a paired-π lane
**only when the wave ships a visual delta** (precept SPEC §"π lane"; adoption
fold §3). A's wave map records the disposition per wave: W0 (docs/hygiene), W1
(build-config), W2 (engine internals), W3 (CI gate) all **skip**—no demo render
delta. W4 was the only PAIRED-π *candidate* (reduced-motion + WAAPI widening
could in principle change a demo scene's rendered motion), and even there the
defensible probe is an animation-timing sample, not a static layout screenshot.

The verdict is **skip**: W4's deltas stayed engine-internal. Reduced-motion
*removes* motion (snaps to the final frame) rather than re-laying-out, the
`scheduler.yield()` batch break changes cadence not output, and the WAAPI spring
`linear()` widening moves the *same* solved curve onto the compositor thread—no
new pixel state. The adoption fold §3 predicted this outcome ("the likely
outcome, since reduced-motion *removes* motion rather than re-laying-out"). There
is no demo-observable pixel change to capture, so A.W5 records the skip rather
than running an empty paired-π.

## § 3.0.0 changeset cut

A is keyframes.js' first tranche and it carries one major. The version moves
2.2.0 → **3.0.0**—a single major bump cut via changeset:

- **WHAT** — a `major` changeset for `@mkbabb/keyframes.js` rendering the
  release: the value.js boundary gated (inv α), the library build glass-ui-free
  (inv β), the boundary ergonomics (eager-resolve closes the silent-linear
  window, one `EasingResolvable` contract), and the engine's modern-web baseline
  (reduced-motion on every path, `scheduler.yield()` in the group compositor, the
  WAAPI spring `linear()` widening).
- **WHY major** — the heavy `Animation`/`AnimationGroup`/`morph` play paths now
  consult `prefers-reduced-motion` (opt-in via `respectReducedMotion`, default
  off) and the boundary's contract is now gated, not asserted. A single major
  carries the whole tranche cleanly rather than fragmenting it across patch/minor
  cuts.

The changeset is the publish artefact (A.md §RESOLVED 1). The tranche owns the
binding question + waves + gates; the changeset stays the release mechanism (the
`Version Packages` PR → tag → `release.yml`).

## § The publish leg — the close

The publish leg is the close of A. It is user-domain (outward-facing,
confirm-first); W1 made it runnable on a clean runner for the first time but does
not run it. The leg:

1. **changeset version** — `changeset version` consumes the `major` changeset,
   bumps `package.json` 2.2.0 → 3.0.0, and renders `CHANGELOG.md` (the
   `Version Packages` PR).
2. **`v3.0.0` tag** — commit the version bump to master, push, then push the
   `v3.0.0` tag.
3. **`release.yml` publish** — the tag triggers `release.yml`, which runs the
   floor (`check:lib` → `build:lib` → `test` → `proof:boundary`) then
   `npm publish --provenance --access public` under `permissions: id-token:
   write`. The boundary gate runs on the publish path: a future light-module
   edit that reintroduces a static value.js edge fails the release, not just CI.

`release.yml` is the only publish path—`node.js.yml` is retired (its test job
duplicated `ci.yml`; its gh-pages deploy was structurally red on a clean runner,
needing the unpublished glass-ui sibling). The demo gh-pages deploy is now a
dev-machine action. The library publishes from CI on a tag, with provenance.
