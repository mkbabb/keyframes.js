# A.W3 — `proof:boundary` gate

**Phase:** IMPLEMENTATION · **Status:** LANDED

The value.js light/heavy boundary stops being a CHANGELOG sentence and becomes a
CI gate. `proof:boundary` builds the real light entry from source, re-runs
tree-shaking, and asserts the spring-only chunk's static module set carries zero
value.js modules and zero static edge to the heavy engine. It bites: a value.js
import reintroduced into a light module turns it red.

## inv α — the boundary is gated, not asserted

> The KF-B1 light/heavy split is proven by a CI gate that builds the real light
> entry and counts value.js modules + static `engine.ts` edges, not by a
> CHANGELOG sentence. A claim about the static graph that no gate measures is not
> an invariant.

`proof:boundary` realizes inv α. It binds every future light-module edit: the
spring/interpolation engines reach value.js **only** through
`loadAnimationEngine()`'s dynamic `import("./engine")`, never through a static
import. The moment a light module grows a static value.js (or `engine.ts`) edge,
the gate fails the build.

## What landed

### `scripts/proof-boundary.mjs` — build-and-count the spring-only entry

The gate proves the boundary **by construction** rather than by inspecting the
pre-built `dist/`:

1. **Spring-only entry from source.** It writes a temporary entry that pulls one
   light symbol off the public barrel —
   `import { SpringProgress } from "src/animation/index.ts"` (proof-boundary.mjs:46-49)
   — and re-runs tree-shaking on the real module graph with `rolldown`. Bundling
   from `src/animation/index.ts` (not `dist/keyframes.js`) means the gate measures
   the *source* graph: it catches a boundary break the instant it lands in a `.ts`
   file, before any build artefact exists.
2. **value.js NON-external — the crux.** Only host-provided / unrelated packages
   are externalized (`external: ["vue", "prettier"]`, proof-boundary.mjs:58).
   value.js and parse-that are deliberately **left in** the bundle. If they were
   externalized, a reintroduced static import would be silently elided as a bare
   `import` and the gate would see nothing. Keeping them non-external forces any
   static edge to pull their *source* into the entry chunk—exactly where the
   assertion below catches it.
3. **Static-moduleId assertion.** It locates the entry chunk
   (`output.find(o => o.type === "chunk" && o.isEntry)`, proof-boundary.mjs:68) and
   inspects `entry.moduleIds` — the chunk's **static** module inputs. A dynamic
   `import("./engine")` lands `engine.ts` and its value.js subtree in a *separate*
   dynamic chunk, not in `moduleIds`, so the dynamic path is invisible to the
   count (as it must be). Two filters run over the static set:
   - `isValueJs` (proof-boundary.mjs:36-38) — matches any module under the value.js
     package (`node_modules/@mkbabb/value.js/` or a `value.js/{dist,src}/` sibling
     checkout). Assertion: **0**.
   - `isHeavyEngine` (proof-boundary.mjs:41) — matches `src/animation/engine.ts`.
     The heavy engine must reach a light bundle only as a dynamic chunk.
     Assertion: **0**.
4. **Exit codes.** Either filter non-empty → it prints the offending module paths
   and `process.exit(1)` (proof-boundary.mjs:105-114). No entry chunk → `exit(2)`;
   a thrown error → `exit(3)` (proof-boundary.mjs:122-125). The temp entry is
   removed in a `finally` (proof-boundary.mjs:64-66), so a failed run leaves no
   stray file.

The success path logs the static-module/value.js-edge/engine-edge counts plus the
dynamic-chunk list (proof-boundary.mjs:81-89), so the green run is *legible*: it
shows the heavy engine present as a dynamic chunk while absent from the static
graph—the boundary's shape, printed.

### CI wiring

`proof:boundary` = `node scripts/proof-boundary.mjs` (a `package.json` script).
It is the terminal step of both library-scoped gate workflows, after the build so
it inspects the same source the build ships:

- **`.github/workflows/ci.yml`** — PR + push-to-master, step order
  `check:lib → build:lib → test → proof:boundary` (ci.yml:41-48). The header
  documents the gate as "build a spring-only entry and count value.js bytes +
  static engine-* edges (A inv α — the boundary is gated)" (ci.yml:10-12).
- **`.github/workflows/release.yml`** — the same library-scoped gate re-runs
  before publish: `check:lib → build:lib → test → proof:boundary → publish`
  (release.yml:39-47). The boundary is verified one last time on the exact commit
  that ships.

Both runs are glass-ui-free (inv β): `proof:boundary` touches only `src/` → the
spring-only entry, and value.js resolves from the registry, so it has no demo /
glass-ui dependency.

## The gate bites — the negative test

inv α is only real if the gate *fails when the boundary breaks*. Verified by a
one-line negative test against the light spring module:

```ts
// src/animation/spring.ts (negative-test injection)
import { lerp } from "@mkbabb/value.js";
```

With that static edge present, `proof:boundary` went **RED**: it reported
`node_modules/@mkbabb/value.js/dist/value.js` as a static input of the spring-only
entry and `process.exit(1)`. The injection pulled value.js source straight into
the entry chunk (because value.js is non-external), and `isValueJs` counted it.
Reverting the import → **PASS**. The gate detects the precise failure mode it
exists to prevent.

## Disposition

- The light/heavy boundary is now CI-gated on every PR, every push to master, and
  every release. inv α is in force.
- `dist/keyframes.js` (~17 KB) stays a value.js-free barrel;
  `dist/engine-*.js` (~26 KB) is the value.js-bearing dynamic chunk reached only
  through `import("./engine")`. `proof:boundary` is green on the landed tree.
- The gate measures the **source** graph from `src/animation/index.ts`, so a
  boundary break is caught at the `.ts` edit, independent of build state.
