# A.W0 — Format reconciliation + hygiene

**Phase**: DEVELOPMENT. **Agents**: 1. **Ships**: no source, no engine code—the
tranche scaffold, the changeset↔tranche contract, the `src/animation/CLAUDE.md`
re-sync, the CI-break issue, the precepts confirmation, and the hygiene sweep.

W0 stands up keyframes.js' first tranche. The engine has run on changesets since
v2.0.0; every other constellation repo runs the bbnf tranche format and keyframes
is the lone hold-out. W0 reconciles the two—it does not replace the changeset—so
`docs/tranches/A/` owns the binding question + waves + gates and the changeset
stays the release mechanism. On that foundation it corrects the one stale
artefact the v2.2.0 KF-B1 boundary left behind (`src/animation/CLAUDE.md`,
documenting pre-extraction geography), files the real CI-break issue, confirms
the precepts gitlink, and clears the scratch cruft the engine had accumulated.

### W0.2 — The changeset↔tranche contract (codified)

**WHAT**: the format reconciliation is written as the resolved-design decision in
`A.md` §Resolved-design-decisions 1 and stated here as the binding contract:

- The **tranche** owns intent—the binding question, the waves, the hard gates.
- The **changeset** stays the publish mechanism: the `Version Packages` PR → the
  `v*.*.*` tag → `release.yml` → `npm publish`. A wave that ships a version writes
  its changeset at close.
- `CHANGELOG.md` is the changeset-rendered **release** record (version-history
  narration lives here and only here).
- `FINAL.md` records the **tranche** close—gates met, overfitting audit,
  deferrals—and does **not** duplicate the CHANGELOG.

**WHY**: keyframes already ran on changesets; the risk in adopting the tranche
format is two records narrating the same release. The contract draws the line
once: tranche = intent + gates, changeset = publish, CHANGELOG = release record,
FINAL = tranche close. No duplication. This is what lets keyframes run the format
without the changeset cadence and the tranche cadence fighting over the same
ground.

### W0.3 — `src/animation/CLAUDE.md` re-sync to the KF-B1 boundary topology

**WHAT**: `src/animation/CLAUDE.md` re-synced to match the live boundary geography.
The old file documented pre-KF-B1 / pre-value.js-extraction topology:

- `index.ts` listed as holding the heavy classes (`Animation`,
  `CSSKeyframesAnimation` "— main classes + re-exports").
- the project-tree paths `../parsing` / `../units` / `../easing` / `../math` that
  the value.js extraction retired.

The re-sync matches the diff against the real tree:

- `index.ts` is the **package barrel + boundary**—light exports +
  `loadAnimationEngine()`; it holds no heavy class and no static value.js edge.
- the heavy classes (`Animation`, `CSSKeyframesAnimation`, `AnimationGroup`,
  `getAnimationId`, `getTimingFunction`, `resolveKeyframes`, the option constants)
  live in **`engine.ts`**, reached only through the dynamic `import("./engine")`.
- leaf math (`clamp`/`scale`/`lerp` + rAF shims, byte-equivalent to value.js)
  lives in **`internal/leaves.ts`**; the dep is `@mkbabb/value.js`, reached by the
  HEAVY surface only.

The re-sync also adds a "The value.js static/dynamic boundary" section (the
LIGHT/HEAVY split + the `proof:boundary` gate), the `internal/` leaf inventory,
and the reduced-motion / `scheduler.yield` / WAAPI-`linear()` facts that land in
the later waves—so the file documents the boundary topology as the IMPL waves
land on it.

**WHY**: `src/animation/CLAUDE.md` is the engine's own map; a map that describes a
geography the extraction retired sends every future reader (human or agent) to the
wrong module. The KF-B1 release moved the heavy classes to `engine.ts` and the leaf
math to `internal/leaves.ts` but never re-pointed the map. The re-sync diff is the
W0 evidence that the map now matches `engine.ts` / `internal/leaves.ts`.
